# Будущая интеграция UE: первое демо

**Статус:** контракт и план, получатель и UE assets ещё не реализованы.
Python-прототип уже умеет отправлять снимки `myo.character_state.v1` на localhost.
Это исходная граница интеграции; она не требует запускать повторную физику руки в UE.

## Порядок реализации

1. Создать небольшой UE-проект и визуальный риг руки с тем же углом/нулевой позой.
2. Реализовать получатель на рабочем потоке: JSON decode, schema/model/config
   validation, проверка чисел и последовательности. На game thread передавать
   последнюю целую копию состояния, не обновлять компоненты из socket thread.
3. Отобразить угол, затем activation, force N, strain и capacity в debug UI.
   Показать время последнего снимка и состояние разрыва соединения.
4. Настроить Animation Blueprint / Control Rig для позы и запись именованных
   animation curves. Один Blueprint float сам по себе не является входом MLD.
5. Сделать активный мышечный риг Flesh и набор targets: фиксированная поза с
   различными активациями, coactivation, расслабление, различные грузы.
6. Если нужен ML Deformer, обучить его на согласованных poses + curves + Geometry
   Cache. Проверить одну позу при разных активациях на отложенных примерах.
7. Измерить CPU/GPU/VRAM и задержку всей цепочки; решить, нужен ли живой Flesh
   для дополнительных динамических эффектов.

## Что необходимо различать

- **Активация** задаёт активное состояние, но не равна силе мышцы.
- **Натяжение** зависит также от длины, скорости, упругости и capacity.
- **Геометрическая деформация** требует собственного рига/материальной модели.
  Входная кривая активации не превращает пассивный Flesh asset в активную мышцу.
- **ML Deformer** учится воспроизводить заданные targets. Он не добавляет
  физическую жёсткость коллизиям MuJoCo и не восстанавливает неизвестное
  контактное состояние из одного угла.
- **Debug-цвет/индикатор усилия** реализуется раньше подробной поверхности и
  должен оставаться доступен для проверки более сложной графики.

Для первой интеграции достаточно Python CPU simulation + UE renderer. URLab
рассматривается как альтернативный путь к native MuJoCo внутри UE после проверки
совместимости, а не как уже готовый адаптер MyoSuite → SkeletalMesh → Flesh.
Custom muscle state и callbacks V0 должны быть перенесены явно; загрузки одного
MJCF недостаточно.

Для URLab авторы заявляют UE5.7; проект alpha, а версия MuJoCo отличается от
проверенной в V0. Поэтому сначала следует зафиксировать точный набор версий и
проверить совпадение dynamics. Подробности и первичные ссылки — в
[architecture.md](../../docs/architecture.md) и [research.md](../../docs/research.md).

## Критерии завершения интеграции демо 1

- Приложением можно управлять в реальном времени; изменение команды меняет
  возбуждение, физику и изображение по общей временной шкале.
- При одной позе видны различия выбранных активаций/усилий и coactivation.
- Графические настройки и просадка FPS не меняют физический timestep.
- Reset/потеря пакетов не смешивают состояния разных эпизодов.
- Проверена исполнительная сборка, а не только окно редактора.
- Есть измеренный бюджет на целевом ПК. Ни выбранный GPU, ни FPS пока не зафиксированы.
