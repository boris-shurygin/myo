# MyoD1: начальная визуальная сцена UE

Состояние на **2026-11-08**: создан проект под **UE 5.8.4, CL 58902052**.
Это пока проект с editor-скриптами, без собственного C++-модуля. Импортированы
32 костных меша MyoArm и созданы четыре статические контрольные сцены.
Добавлены шесть поверхностей BodyParts3D с предварительной подгонкой и статическими
позами; [методика и ограничения](../../../docs/bodyparts3d.md).
Получатель live-телеметрии, Skeletal Mesh rig, активное
сокращение Flesh, кожа и упакованная standalone-сборка ещё не готовы.
Статическую сцену можно открыть отдельным вьювером через установленный движок.
Освещение поверхностей сглажено с сохранением резких перегибов; геометрия
пока остаётся упрощённой. У двух источников света назначены разные приоритеты,
чтобы убрать предупреждение о конкурирующих DirectionalLight.

## Открыть вьювер

Из `D:\myo`: `.\view-arm.cmd`.
Или `.\view-arm.cmd -Pose 45 -Seconds 60`: позы15/45/90/120°.
Для первого мышечного вида: `.\view-arm.cmd -View muscles`.
Открывается окно UE `-game` без редакторских панелей; камера настроена автоматически.
Мышь — поворот, WASD — перемещение, Q/E — вниз/вверх, Home — исходный вид,
Esc — закрыть. Шар у кисти — груз; отдельный летающий шар навигатора убран.
По умолчанию опыт длится120 s, DX11, 640×360, cap20 FPS; ограничения CPU/памяти
сохраняются. Подготовка ресурсов и результаты — в
[инструкции просмотра](../../../docs/unreal-load-profiling.md#просмотр-сцены).

## Подготовка Windows

Из корня репозитория, в PowerShell:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/setup-windows.ps1
.\.venv\Scripts\python.exe scripts/prepare_myoarm.py
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/unreal.ps1 -Action Probe
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/unreal.ps1 -Action PrepareBones
```

Windows bootstrap использует нативный `.venv\Scripts\python.exe` версии 3.12;
Linux-команды с `.venv/bin/python3` здесь не подменяются системным Python или WSL.
`uv` должен быть установлен. Существующее несовместимое окружение скрипт
сохраняет на месте и отклоняет. Установка base/dev не включает обучение.
Для полного pytest текущие тесты дополнительно требуют optional `train`:
несколько модулей импортируют эти зависимости без `importorskip`.

`-EngineRoot` позволяет указать другой путь к **той же** сборке UE; версия
и changelist проверяются по `../engine-version.json`. Обновление движка требует
отдельной проверки. Источники, производная анатомия и сгенерированные `.uasset`
остаются локальными в игнорируемых `data/` и `Content/Generated/`.
Скрипты не меняют физику и не включают обратные силы из UE.

## Что проверяют команды

- `Probe`: загрузка Flesh/Dataflow и поставляемых Epic templates, создание узла
  графа через отражённый Python API. Это не тест активного сокращения.
- `PrepareBones`: экспорт из скомпилированной MuJoCo-модели, создание Static Mesh
  и уровней `L_Bones_15`, `L_Bones_45`, `L_Bones_90`, `L_Bones_120` в
  `/Game/Generated/Bones_v1/`. Проверяются размеры и число треугольников каждого
  меша; физическая симуляция не запускается.
- `FleshProbe`: экспериментальный пассивный tet-образец. На проверенной сборке
  повторная загрузка сохранённой коллекции вызывает engine `ensure` проверки
  версии GeometryCollection. Этот этап **не пройден**; подробности в
  [журнале проверок](../../../docs/validation.md).

Вход экспорта — `configs/d1_myoarm.json`; результат —
`data/unreal/myoarm/geometry.json` и файлы мешей с SHA-256.
`myo.unreal_geometry.v1` — отдельный формат подготовки геометрии, а не замена
телеметрии `myo.character_state.v2`. Есть иерархия bodies и локальные смещения
скомпилированных mesh geoms; полного экспорта attachment/wrap landmarks пока нет.

Граница `MyoToUnreal` использует `S=diag(1,-1,1)`: m→cm, отражение Y,
`R_UE=S R_Myo S^-1`, quaternion xyzw и смену обхода треугольников.
Не применять поверх неё преобразование осей FBX. MuJoCo уже преобразует
вершины в собственную principal frame; соответствующее смещение geom
учитывается отдельно. Неманифолдные участки исходных STL импортируются как
независимые render-треугольники: это сохраняет грани, но не исправляет топологию
для Flesh. UV0 — простая диагностическая проекция, не текстурная развёртка анатомии.

## Следующий графический запуск

Для постепенных измерений добавлен отдельный
[ограниченный profiler](../../../docs/unreal-load-profiling.md): baseline →
NullRHI → короткий пустой renderer → костная сцена. Он ограничивает дерево
процессов через Windows Job Object и сохраняет отсчёты до остановки.
Новый опыт начинается отдельной командой после оценки предыдущего.

Первый offscreen-запуск редактора не завершил захват кадров; пользователь
сообщил о полном зависании ПК. В логе было 9 локальных shader workers.
Причина системного зависания не установлена. После исправления сохранения мешей
кадр позы90° проверен; остальные позы пока не прошли визуальную приёмку.

После этого в launcher добавлены `-corelimit=2` и явное включение графики;
FPS проекта ограничен30. Затем отдельным profiler выполнены короткие DX11-пробы
при10 и20 FPS с affinity на два логических CPU и hard limit6 GiB commit дерева.
Загрузка костной сцены подтверждена логом; финальная90 s проба при cap20 FPS:
пик commit3.36 GiB, общая VRAM1374 MiB, GPU52°C, без срабатывания порогов. Полные результаты —
в [validation.md](../../../docs/validation.md). Это ещё не визуальная приёмка
и не проверка прежнего DX12-запуска или холодной компиляции шейдеров.

Для намеренного ручного открытия сцены:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/unreal.ps1 -Action Open -EnableRendering
```

`Capture -EnableRendering` предназначен для автоматических кадров четырёх
поз, но пока не проверен до конца. `Probe` и `PrepareBones` используют `NullRHI`.
Launcher направляет пользовательские файлы в `.cache/unreal/User`, DDC — в
`.cache/unreal/DerivedDataCache`, используя файловый кэш без локального Zen.
Отчёты лежат в `.cache/unreal/User/Saved/Myo/`. Успех Python не перекрывает
ненулевой exit code редактора: launcher учитывает оба результата.

## Дальнейшая работа

Сначала вручную проверить четыре позы при ограниченной нагрузке, затем
устранить воспроизводимый Flesh blocker на маленьком образце и доказать
изменение формы от одной activation curve при неподвижных костях.
Далее — общий риг, JSONL replay и локальный bridge, одна анатомическая мышца,
шесть мышц, подкожный слой и кожа. Общий
[план](../../../docs/desktop-unreal-preacher-plan.md) остаётся программой работы.

Visual Studio C++ и Windows SDK в проверенных стандартных каталогах и реестре
не обнаружены; компиляция собственного модуля не выполнялась. `.vsconfig`
перечисляет выбранные компоненты MSVC 14.44 / SDK 22621 по требованиям
установленного UE. Они ещё не установлены и не проверены сборкой.
