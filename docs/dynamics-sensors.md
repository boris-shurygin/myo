# Дополнительные сенсорные входы предиктора

## Что добавлено

К большой сети из [опыта с ускорением](dynamics-acceleration.md) добавлены
два канала для каждой из шести мышц:

- Средняя скорость изменения длины волокна за предыдущие 20 ms, m/s.
  Положительное значение означает удлинение. При reset скорость нулевая;
  история не переходит между эпизодами.
- Текущая сила сухожилия, N. Длина волокна уже присутствовала во входе.

Это численные аналоги сенсорных сигналов, а не модель мышечных веретён или
сухожильных органов Гольджи. Прежние входы, включая activation и capacity proxy,
сохранены; биологическая доступность всех признаков этим опытом не установлена.
Отдельные рецепторы нагрузки сустава пока не добавлены.

Нейронный вход вырос с 26 до **38**, архитектура теперь
`38 → 1024 → 1024 → 512 → 20`, **1624596 параметров**. Предсказываются прежние
20 физических приращений; очередь команд с транспортной задержкой сдвигается
точно. Полное состояние развёртки тоже имеет 38 чисел, но другой состав:
прежние 32 плюс шесть прошлых длин волокна. Эти шесть значений копируются
из текущего состояния при каждом переходе и позволяют вычислить скорость.

При развёртке модель использует собственные предсказанные длины и положение.
Будущие измеренные скорости/силы не подставляются. Сила вычисляется как
`k_tendon * max(L_path(q) - L_fiber - L_slack, 0)`. Длина пути берётся из
дифференцируемой линейной интерполяции фиксированной геометрии MyoArm:
2049 узлов от 0 до 160°. Вне таблицы используется линейная экстраполяция,
без обрезания прогнозируемого угла. Все наблюдаемые углы набора внутри таблицы.
На 216 native-показаниях RMSE силы составила **0,00141 N**, максимум
расхождения **0,00566 N**. Это проверка воспроизведения текущей модели силы,
не анатомической точности. Расчёт признаков не меняет физическое состояние.

Сила здесь — производный признак известных геометрии и закона сухожилия;
она не добавляет независимой информации о состоянии. Скорость добавляет один
предыдущий интервал. Поэтому опыт проверяет пользу такого представления,
но не разделяет вклад двух новых групп: для этого нужны отдельные абляции.

## Контролируемое сравнение

Повторены 2000 обновлений с seed 0, batch 128, Adam lr 0,001, clip 10 и
шестишаговым BPTT. Сохранена потеря предыдущего опыта: локальное среднее
ускорение каждого интервала 20 ms и прежние ошибки остальных физических
каналов. Новые сенсоры являются входами, отдельная ошибка за них не добавлена.

Те же 72 эпизода, разделение целыми эпизодами 36/18/18, исходная механика
с задержкой, активационной динамикой и упругими сухожилиями. Новых траекторий
для обучения не собирали. Все исходные состояния и действия совпали точно;
добавлена только причинная история длин. Normalization вычислена по train,
общие статистики совпали с предыдущими. Дополнительные столбцы первого слоя
инициализированы нулями, прежние веса и начальная функция сохранены.

Оба критерия выбора checkpoint, по ускорению и по скорости validation,
выбрали одинаковые веса на update 1900. Обучение с validation заняло 169 s,
весь запуск с оценкой — 214 s на ноутбуке; это не изолированный бенчмарк CPU.

| Метрика test | Без новых входов | С новыми входами |
| --- | ---: | ---: |
| Скорость через 20 ms, RMSE rad/s | 0,20794 | 0,20772 |
| Скорость через 120 ms, RMSE rad/s | 0,40916 | 0,38375 |
| Скорость через 400 ms, RMSE rad/s | 0,43273 | 0,41744 |
| Ускорение 0–20 ms, RMSE rad/s² | 10,39675 | 10,38589 |
| Ускорение 100–120 ms, RMSE rad/s² | 10,21920 | 9,99344 |
| Ускорение 380–400 ms, RMSE rad/s² | 10,30039 | 10,48575 |

Ускорение — среднее за последний интервал 20 ms, не за весь горизонт.
На 120 ms ошибка скорости уменьшилась примерно на 6%, ускорения на 2%.
Устойчивого улучшения всех показателей нет: на 400 ms ускорение хуже.
Один запуск не устанавливает статистическую устойчивость результата.

Проверка производных использовала те же 36 native-состояний и 2808 управляющих
шагов; эталонные Jacobian MuJoCo совпали точно. Совокупная ошибка Jacobian
скорости после задержки выросла **0,772 → 0,854**, cosine **0,365 → 0,338**.
Для Jacobian ускорения RMSE уменьшилась **37,746 → 35,380**, совпадение знака
значимых элементов выросло **59,8% → 62,6%**, но cosine остался около **0,10**.
До 40 ms влияние новой команды равно нулю, как требует очередь задержки.
Производные всё ещё недостаточно точны для надёжного обучения actor через
этот предиктор. Новый контроллер и его поведение в демо здесь не проверялись.

## Воспроизведение и результаты

```bash
.venv/bin/python3 -m myo.train_dynamics_sensors \
  --reference runs/d1_dynamics_acceleration \
  --output-dir runs/d1_dynamics_sensors_new
```

Нужны прежние локальные данные и установленные зависимости обучения.
Результаты выполненного запуска находятся в игнорируемом
`runs/d1_dynamics_sensors/`: `summary.json`, `independent_evaluation.json`,
`final_artifact_check.json`, два совпадающих checkpoint с metadata,
`comparison.png/svg`, `acceleration.png/svg`, `training.png/svg`.
Контракт `myo.action_dynamics_sensors.v1` фиксирует порядок входов, шаг,
геометрию, параметры сенсоров и исходники; прежний загрузчик отвергает новую
схему. Прежние checkpoints загружаются прежним загрузчиком.

Реализация: `src/myo/dynamics_sensors.py`, запуск:
`src/myo/train_dynamics_sensors.py`. Результаты проверок — в
[validation.md](validation.md).
