# Диагностическое окно руки на Linux

Окно MuJoCo показывает состояние физической руки и принимает команды угла и
триггера. Unreal для этого не нужен. У MyoArm используются исходные меши костей
и пространственные мышечные пути той же модели, что рассчитывает силы.
Вдоль каждого пути отдельно показаны мышечное брюшко и сухожильные участки:
цветом — активация и натяжение, длиной и толщиной — их деформация.
Это процедурная диагностическая геометрия; анатомические поверхности мышц и кожа
ещё предстоят.

## Запуск

После [установки Python 3.12](installation.md) и
[подготовки локальных assets MyoArm](myoarm.md):

```bash
source .venv/bin/activate
python3 -m myo demo --config configs/d1_myoarm.json
```

По умолчанию запускается диагностический `heuristic`. Для отдельного
нейросетевого варианта уже подготовлен локальный imitation actor:

```bash
python3 -m myo demo --controller runs/d1_actor_calibrated_transitions.zip
```

Рядом требуется `.zip.metadata.json`; `--config` здесь не нужен, используется
сохранённая конфигурация. Этот итоговый checkpoint и его метаданные включены
в репозиторий по решению владельца: после клонирования достаточно установить
окружение и подготовить MyoArm, повторное обучение для запуска не требуется.
Остальные артефакты `runs/` остаются локальными. Команды этапов приведены
в [журнале проверок](validation.md); исправленный отбор весов может изменить
результат повторения исторических запусков.

Этот actor обучен по демонстрациям и исправлениям heuristic на собственных
состояниях и самостоятельно выдаёт возбуждения в runtime. После изменения
силы мышц, утомления и верхнего диапазона нужны новые веса: прежние
`d1_actor_initial.zip` и `d1_actor_corrected.zip` отвергаются проверкой физики.
Это не независимо найденная защитная policy. Результаты завершённого обучения
и проверок поведения — в [validation.md](validation.md); происхождение
параметров — в [calibration.md](calibration.md).
Промежуточные этапы имели разные регрессии: даже успешный короткий проход 155°
не означал устойчивого удержания и расслабления после утомления. Последний
вариант `calibrated_transitions` обучен также на раздельном утомлении групп мышц
и физически достигнутых состояниях около вертикали.

В проверке с грузом 1 kg он удержал цели 75°/125° по пять минут и полностью
расслабился после отпускания. Отдельный подъём от 75° к 155° завершился на
155.20°: сгибатели расслаблены, удерживает трицепс. Обратный проход
155° → 145° → 60° проверен. Резкая смена 125° → 155° пока приводит к потере
управления; отсутствие верхнего упора не означает освоение всех переходов.

Для проверки прежней схематической V0 без сторонних assets:

```bash
python3 -m myo demo
```

Нужен графический дисплей. Окно работает до закрытия; `--seconds 20`
ограничивает просмотр двадцатью секундами симуляции. Темп ограничен реальным
временем, а физический шаг остаётся фиксированным. **Автоматического перезапуска
по учебному лимиту времени в окне нет:** время, поза, команды, активации, история
и очереди задержки продолжаются без сброса. `rollout --viewer` использует тот же
непрерывный режим до заданного `--seconds`; `rollout` без окна сохраняет обычные
эпизоды для экспериментов.

Если состояние сустава выходит за допустимые границы симуляции, окно показывает
`STOPPED` с причиной и сохраняет последний кадр. **R** начинает заново;
**Space** такую остановку не снимает.

## Управление

| Действие | Клавиша |
| --- | --- |
| Увеличить / уменьшить желаемый угол на 5° | **↑ / ↓** |
| Увеличить / уменьшить триггер на 0.1 | **+ / −** |
| Отпустить триггер | **0** |
| Мышцы по активации, сухожилия по нагрузке — основной вид | **1** |
| Весь путь по активации / силе / растяжению сухожилия | **2 / 3 / 4** |
| Следующая мышца в числовой панели | **M** |
| Пауза / продолжение | **Space** |
| Перезапустить эпизод | **R** |
| Вернуть камеру к руке | **F** |
| Закрыть окно | **Esc** |
| Вращать и приближать вид | Мышь, стандартное управление MuJoCo |

Угол сохраняется после отпускания клавиши. На экране отдельно видны запрошенный
угол и текущая сглаженная цель контроллера. Стрелки не меняют физическую позу.
Триггер задаёт предпочитаемый предел произвольного возбуждения. **0** меняет
команду на расслабление; очередь задержанных команд и активация не сбрасываются,
защитное возбуждение не умножается на ноль. Действительный результат зависит от
контроллера и нагрузки, а не от самой клавиши.

У MyoArm верхнего ограничения угла больше нет, включая прежнее мягкое
сопротивление возле 130°. Нижний предел 15° сохранён. При отпускании с грузом
1 kg рука может спокойно лежать около 17.17° благодаря пассивному сопротивлению.
Команда точно держать 15° с полным триггером требует усилия против этой опоры;
для расслабления используется **0**.

Примерно после 161.5° исходные пути трицепса меняют знак плеча. Окно показывает
`Muscle path reversal: outside source anatomy range`, но не вводит новый
ограничитель. Позиции за этой границей — диагностика экстраполяции геометрии.

Клавиши команд доступны в `interactive` и `curriculum`. В `demo` сохранённый
curriculum сразу заменяется ручными командами. При запуске `demo` и нажатии **R**
масса берётся из сохранённой конфигурации (для D1 — 1 kg), а capacity начинается
с 1.0. Учебная рандомизация больше не делает этот запуск незаметно тяжелее;
дальше capacity меняется по обычной модели утомления и восстановления.
В `rollout --viewer` переход к ручным командам происходит
при первом нажатии клавиши команды. В режиме
`reference` выполняется исходный синусоидальный опыт, стрелки и триггер выключены.
При паузе можно выбрать следующую команду; движение возобновляется с **Space**.

Боковые панели MuJoCo скрыты при открытии. **Tab** и **Shift+Tab** могут показать
их снова. Изменения через отладочные панели и перетаскивание объектов действуют
на копию визуализатора и не становятся командами физической среды.

## Что показывает цвет

Основной режим **Tissues** одновременно использует две фиксированные шкалы.
Мышечное брюшко меняется от серо-синего через голубой и оранжевый к красному
по мере роста активации. Сухожилие меняется от светлого через жёлтый и оранжевый
к малиновому по мере роста натяжения. Обе легенды показаны внизу слева.

| Режим | Величина и диапазон цвета |
| --- | --- |
| **1 — Tissues**, по умолчанию | Брюшко: активация 0–100%; сухожилия: натяжение 0–100% F0 |
| **2 — Activation** | Весь путь: активация мышцы после задержки и фильтра, 0–100% |
| **3 — Force** | Весь путь: натяжение сухожилия / исходная максимальная изометрическая сила этой мышцы, 0–100% F0 |
| **4 — Strain** | Весь путь: относительное растяжение сухожилия, 0–4% |

В режимах 2–4 используется единая шкала от серо-синего к красному.
Сила может превосходить F0, а strain — 4%: тогда цвет остаётся на верхнем краю, но
числовая панель показывает полное значение. Верхний край цветовой шкалы не
означает медицинский предел. Равный цвет силы означает равную долю F0;
силы в ньютонах у разных мышц могут отличаться.

В панели выбранной мышцы отдельно показаны отправленное возбуждение, задержанное
возбуждение, активация, натяжение в N, растяжение сухожилия, длины волокна и
сухожилия в mm, а также capacity proxy. Внутри физики используются SI; mm и
градусы — только формат изображения. Все мышцы получают независимые команды; одинаковый цвет сам по
себе не означает одинаковую силу или общий канал управления.

## Геометрия и ограничения

У MyoArm сохранены плечевой пояс, плечевая, лучевая и локтевая кости, кисть и
проксимальные точки прикрепления. Подвижен только локоть. Шесть отображаемых
мышечных путей: `BIClong`, `BICshort`, `BRA`, `TRIlong`, `TRIlat`, `TRImed`.
Процедурные объёмы следуют прикреплениям и огибаниям механической модели:
сохраняются участки дуг, которые строит MuJoCo. Маркеры отмечают начало и конец
каждого пути.

Длина брюшка берётся из состояния мышечного волокна, суммарная длина сухожилий —
из независимого последовательного упругого состояния. При удлинении ткань
становится тоньше, при укорочении — толще: радиус меняется приблизительно как
`sqrt(L_ref / L)`, что даёт приближение постоянного объёма. Поэтому изменение
длин тканей меняет изображение и при той же позе костей. Активация отдельно
управляет цветом мышечного брюшка.
Для провисшего сухожилия толщина сохраняется исходной: закон уменьшения радиуса
действует при растяжении сверх slack length. При нулевой длине отдельного
сухожильного сегмента нет; бесконечного утолщения не возникает.

В физической модели сухожилие представлено одной суммарной длиной. Для изображения
она поделена поровну между двумя концами пути. Это условное распределение 50/50;
границы тканей и исходные радиусы не измерены по анатомическим поверхностям.
Силы, длины и положения костей такая визуализация не изменяет.

При `geometry="toy"` кости и пути четырёх мышц остаются условной схемой,
построенной отдельно от постоянных плеч моментов V0. Новое разделение тканей
передаёт на эти пути соотношение длин мышц и сухожилий. Такая картинка не
используется как геометрическая основа MyoArm.

Окно показывает изменение формы диагностических объёмов по состоянию одномерных
мышечных приводов. Здесь нет анатомических мышечных мешей BodyParts3D,
объёмного расчёта тканей в Chaos Flesh, подкожного слоя и кожи. Эти компоненты
и возможный ML Deformer относятся к следующему визуальному этапу на машине
с Unreal.

Окно использует отдельную копию MuJoCo model/data. Свежие преобразования для
отрисовки рассчитываются на этой копии; чтение изображения не делает шага
основной симуляции. Для проверки поз без окна доступен
`myo.demo.render_frame(env, color_mode="tissue")` с `MUJOCO_GL=egl`.
Фактические запуски и ограничения перечислены в [validation.md](validation.md).
