# MuscleMimic на вертикальном стенде

Опыт начат 2026-11-06. Это перенос конкретной методики на другой механизм,
а не воспроизведение опубликованных полнотелых результатов или GPU backend.

## Какой оригинал повторяем

Зафиксирован официальный репозиторий MuscleMimic, commit
`47b653db2bce25de834360d2ee6b2dd88142bd78`, конфигурация
[bimanual/conf_bimanual.yaml](https://github.com/amathislab/musclemimic/blob/47b653db2bce25de834360d2ee6b2dd88142bd78/bimanual/conf_bimanual.yaml).
Она относится к фиксированному основанию и потому ближе нашему стенду.
Таблица опубликованного checkpoint в
[статье v1, Appendix D](https://arxiv.org/html/2603.25544v1#A4)
описывает другую, 16-слойную сеть и иной rollout. Эти настройки не смешиваем.

Оригинальные `networks.py`, `optimizer.py`, `loss.py`, `rollout_buffer.py`
выполняются непосредственно через importlib. Их код не переписан на PyTorch
или SB3. Публичные исходники с Apache-2.0 license хранятся в игнорируемом
`data/musclemimic_methodology`; checksum каждого используемого файла закреплён
в `configs/vertical_mimic_sources.json`. Чужие модели, motion capture, weights,
AMASS/SMPL assets не скачиваются. Сетевая телеметрия не запускается.

## Что повторяем, что адаптируем

| Часть | Порядок опыта |
| --- | --- |
| Задача | Imitation кинематической траектории; не задание ускорения |
| Reference | Аналитические синусы/удержание вместо motion capture; train/validation/test — разные параметры движения |
| Reset | Случайные train-клип и его кадр; q/v из reference; начальные excitation/activation/очередь равны нулю |
| Наблюдения | q/v, длины/скорости/силы/возбуждения/активации мышц, текущее положение/ориентация/скорость mimic site, motion phase, previous raw action |
| Preview | Пять reference-кадров 0/200/400/600/800 ms; q/v и site position; край клипа ограничивается последним кадром |
| Дополнительные каналы | Доставленное возбуждение, отдельные fiber lengths и FIFO для нашей податливой/задержанной механики |
| Actor/critic | Оригинальные отдельные MLP 4×1024, SiLU, LayerNorm ε=1e−5, ортогональная инициализация, без residual |
| Распределение | Оригинальный diagonal Gaussian; обучаемая state-independent std, начальная 0,2; линейный mean, без tanh на выходе |
| Физическое действие | DefaultControl для ctrlrange [0,1]: `u=clip((a+1)/2,0,1)`; PPO считает log probability исходного Gaussian action |
| Нормализация входа | Оригинальный RunningMeanStd/Welford; как в source runner, статистики сохраняются на rollout и не сохраняются при minibatch update |
| Нормализация reward | NumPy-перенос NormalizeVecReward; gamma=0,99, reward делится на std discounted return, без вычитания среднего |
| PPO | Оригинальные loss и GAE; gamma=0,99, lambda=0,95; clip actor/value 0,2; vf_coef=0,5; entropy_coef=0 |
| Данные | Rollout по 20 шагов в независимых экземплярах native-физики; перемешивание по времени/средам, 32 minibatch, ровно одна эпоха |
| Optimizer | Оригинальный Muon: beta=0,95, Nesterov, 5 Newton–Schulz шагов, adaptive=false; Adam fallback для векторов; global grad norm ≤1 |
| LR | Постоянный 0,0004: в закреплённом config anneal_lr=false, поэтому строка warmup_cosine не включает schedule |
| Weight decay | Фактически 0 у Muon/Adam: build_optimizer не передаёт верхнеуровневые 0,001 в Muon; переносим исполняемый код, не исправляем молча |
| Граница эпизода | Bootstrap и перенос GAE обрываются на любом done, как в source runner, включая конец клипа/horizon |
| Остановка эпизода | Ошибка moving site >0,25 m, native физический срыв ±0,28 m; конец reference или наш horizon 1000 вместо 30000 source-config. Клип ≤800 шагов, поэтому оба horizon здесь не ограничивают его |
| Timing | Controller 100 Hz, физика 1 kHz; это отличается от предыдущих опытов с controller 50 Hz |
| Backend/масштаб | Native MuJoCo CPU вместо Warp; число сред и бюджет меньше 8192 и 2,048 млрд шагов источника, записываются в metadata |

Физика четырёх вариантов стенда сохраняется: 1 — без compliance/delay/activation
dynamics, 2 — податливые мышца/сухожилие, 3 — также motor delay 40 ms,
4 — также activation 15/50 ms. В MuscleMimic нет нашего отдельного упругого
сухожилия и transport FIFO, поэтому даже точный перенос алгоритма не делает
эти физические задачи одинаковыми. Состояние q/v меняется только при reset;
во время движения груз интегрирует native MuJoCo.

Объём входа: **54 / 56 / 64 / 64**. Сохраняем 3D site features, в том числе
тождественные нули несуществующих направлений. Это делает отображение на
исходную постановку явным, но не добавляет степеней свободы.

## Награда

`e_q=q-q_ref`, `e_v=v-v_ref` на новом кадре после физического шага.
Веса взяты из закреплённого config, температуры — defaults MimicReward:

```text
r = max(0,
    0.1 exp(-10 e_q²) + 0.1 exp(-2 e_v²)
  + 2.0 exp(-100 e_q²/3) + 0.2
  + 0.5 + 0.5 exp(-0.1 e_v²/3)
  - min(1, 0.01 mean(max(|a|-1,0)²)))
```

У одной поступательной степени свободы joint/site position совпадают по
ошибке, как и joint/site linear velocity. Ориентация и угловая скорость
тождественно совпадают с reference и дают постоянные 0,2+0,5. Их не удаляем:
это было бы изменением исходной reward. Отдельных штрафов effort/change здесь
нет: source defaults отключают их. Максимум reward — 3,4, а не 1.
Деление на 3 берётся из исполняемого `MimicReward`: он усредняет по всем
xyz-компонентам, включая нулевые x/y, а не сначала суммирует квадрат нормы
по каждому site. Формула в статье использует другое обозначение;
в этом опыте приоритет у закреплённого кода.

Численная проверка исполняет соответствующий AST-блок исходного `MimicReward`
на fixture одного moving site и сопоставляет его с реальным шагом адаптера.
Она отдельно защищает деление на 3 от повторения ошибки. Предварительный
прогон с квадратом нормы вместо покомпонентного среднего остановлен до test;
сохранён отдельно в `runs/vertical_mimic_site_mean_pilot` (46/27/26/13 полных
updates по вариантам). Основное обучение начинается с новых весов.

Награда не является размеченным возбуждением или дифференцируемой ошибкой
ускорения. PPO связывает стохастические действия с returns через исходную GAE;
градиента через native физику нет. Показанные будущие reference-кадры известны
из задания, не вычислены по будущим результатам действий.

## Оценка

Validation содержит восемь эпизодов: четыре клипа с началом в 0 и 35%.
Test — пять других полных клипов с начала, включая четыре движения и удержание.
Опубликованному критерию completion при пороге 25 cm добавляем отдельно
**строгую инженерную приёмку**: полный клип, position RMSE ≤10 mm и
velocity RMSE ≤0,05 m/s. Completion само по себе не означает точное движение.
Best выбирается по validation: средняя position RMSE, за незаконченный клип
назначается 0,3 m. Test обученных policy вычисляется после окончания отбора.
Нормализация при оценке обновляется в частной копии statistics; в обучение и
checkpoint эта копия не возвращается.

Test тоже стартует с reference q/v, с нулевыми muscle activation/очередью.
Поэтому это оценка продолжения заданного движения; запуск из произвольной
позы/покоя, восстановление после толчка и произвольная новая команда ускорения
здесь не проверяются. Приёмка кинематики также не устанавливает естественность
коактивации: исходный config не штрафует activation energy и не учит EMG.

У концов клипа future reference ограничен последним кадром, как в оригинале.
У наших синусов последний q возвращается к начальному, но v не равна нулю:
получается постоянный q и ненулевой v в обрезанной части preview. Это возможный
источник хвостовых ошибок; отдельной абляции границы пока нет. На графике
train ошибка первых коротких rollout из reference-reset не равна качеству
полного эпизода: поэтому при отборе используются полные validation-клипы.


## Воспроизведение

По умолчанию используется Muon. Для отдельного сравнения доступен
`--optimizer adam`: исходный AdamW с weight decay=0 (то есть Adam),
eps=1e−5 и тем же LR=0,0004. Выбор записывается в metadata и восстанавливается
вместе с состоянием соответствующего optimizer. Checkpoints первоначального
Muon-прогона поддерживаются по явно закреплённому прежнему SHA256 trainer;
произвольное несовпадение исходников по-прежнему отвергается.
Результаты абляции: [Adam против Muon](vertical-mimic-optimizers.md).

```bash
uv pip install --python .venv/bin/python3 '.[mimic]'
.venv/bin/python3 scripts/prepare_musclemimic_methodology.py
.venv/bin/python3 -m myo.train_vertical_mimic \
  --variant 1 --output-dir runs/vertical_mimic/variant_1 \
  --num-envs 128 --updates 128 --hidden 256 256 256 256 --eval-every 16
```

Все результаты и checkpoints остаются в игнорируемом `runs/`. Они содержат
исходный optimizer, input normalizer, полный physical/timing/action contract,
identity публичных исходников, версии JAX/Flax/Optax и hash весов. Старые SB3
checkpoints не подходят к этому протоколу.

## Фактический прогон

Во всех четырёх вариантах использована сеть **4×256** (ширина уменьшена относительно
закреплённого config), 128 независимых сред, 128 updates, 327 680 transitions на
вариант. Все четыре policy обучены с нуля, seed=0. Физические экземпляры независимы,
но на CPU шагают последовательно; сетевые вычисления используют общий batch.
Каждый вариант получает одинаковый бюджет. Конечный бюджет не устанавливает
плато, если кривая ещё улучшается.

| Механика | Best step | Train strict | Test completion | Test strict | Test q RMSE, mm | Test v RMSE, m/s | Constant q RMSE, mm |
| ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 1 | 327680 | 2/6 | 5/5 | 2/5 | 11.58 | 0.036 | 41.55 |
| 2 | 327680 | 1/6 | 5/5 | 2/5 | 10.75 | 0.043 | 44.40 |
| 3 | 327680 | 1/6 | 5/5 | 1/5 | 18.97 | 0.049 | 46.73 |
| 4 | 327680 | 0/6 | 5/5 | 0/5 | 20.62 | 0.052 | 48.61 |

RMSE считается по прожитой части клипа и при раннем обрыве может быть
обманчиво низкой — поэтому рядом стоят completion и строгая приёмка.
Constant support игнорирует reference и выдаёт постоянное исходное возбуждение,
вычисленное для q=0; начальные activation/очередь при этом тоже нулевые.

Диагностический controller использует PD 28/9, известное ускорение reference,

Он не инвертирует точно compliance и не задаёт мышечных labels для PPO.
Для него заранее проверялась выполнимость test-команд; эти данные не были
скрыты от автора протокола. Обученные PPO до окончания отбора на test не проверялись.

Stochastic test — один фиксированный поток случайности seed=321; это
диагностика шума, не многосидовая оценка устойчивости. Std в таблице относится
к last, а исполнение оценивает best; эти checkpoints могут отличаться.

![Кривые обучения и test-движение](../runs/vertical_mimic/comparison.png)

Независимая проверка: **12** строгих загрузок и **20** test-траекторий, точно воспроизведённых
в чистом VerticalMuscles по записанным возбуждениям. Проверены
mapping Gaussian→excitation, delivered excitation, activation, q/v и время.

Размер основной сети: 427,781 trainable параметров
actor+critic для варианта 1. В замере 32 сред сеть 4×1024 тратила
136,65 и 140,90 s на первые два updates; 4×256 после компиляции —
2.93 и 2.74 s.
Это замер одного laptop CPU, не оценка оригинального GPU pipeline.

Таблицы не являются контролируемой абляцией прежней награды ускорений:
изменились сама задача, reset, preview, observation, частота, сеть, распределение
действий, нормализация, optimizer и PPO batching. Улучшение не позволяет
приписать эффект одному из этих компонентов. Полная постановка MuscleMimic
на Warp, 8192 среды, опубликованная 16-слойная сеть и миллиардный бюджет
здесь не воспроизведены.
