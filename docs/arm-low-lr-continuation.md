# Продолжение обучения руки с LR0,0001

Протокол согласован **2026-11-08**, после
[раздельной проверки гипотез](arm-hypotheses.md). Цель — проверить, как далеко
можно довести уже обученную policy более устойчивой поздней оптимизацией.
Это продолжение одного процесса, не серия новых инициализаций/seed.

## Условия и остановка

Родитель — `runs/arm_hypotheses/lr_1e4_none/best.zip`,163840 transitions,
LR1e−4, без предиктора. Его validation4,233°;3/9, test4,002°;4/11 — исходные
ориентиры, не новая оценка результата продолжения.

Сеть, direct Beta excitations, RMSprop moments, reward,27 train-пар и их порядок,
40-ms transport,15/50-ms activation, series elasticity, контакт, груз1 kg и
trigger1 сохраняются. Timestep20 ms, физика1 ms. Один restart среды/RNG seed0
при загрузке родителя; далее между блоками нет reset процесса, RNG или optimizer.
Физические эпизоды по4 s по-прежнему заканчиваются и сбрасываются штатно.

- Блок32768 transitions, native validation каждые8192.
- Продвижение — уменьшение средней tail RMSE с равным весом целей хотя бы на1%
  относительно последнего значимого улучшения **либо** больше pass без ухудшения
  этой средней. Сначала учитывается уменьшение failures; их рост не считается
  улучшением. Малые изменения могут накопиться до порога1%.
- Два полных блока подряд без такого продвижения → остановка и анализ.
- Все9 validation-сценариев проходят → остановка для просмотра policy.
- Исходный выбор `best.zip` по failures/pass/RMSE не меняется; минимум ошибки
  с равным весом целей отдельно сохраняется в `balanced_best.zip` для диагностики.
  Каждый8192-step checkpoint также сохраняется, чтобы не потерять улучшение
  средней ошибки при меньшем числе pass.

Для проверки шумового разрыва после каждого блока сравниваются средние команды
и два fixed stochastic streams0/1 на20→75°,75→20°,25→105°,60→60°.
Sampling выполняется в независимых native env и `torch.random.fork_rng`:
проверки не расходуют RNG обучения и не изменяют его физический эпизод.
Два новых behavioral tests защищают эту изоляцию и известный случай ложного
прогресса при специализации на75°.

PPO по-прежнему собирает1024 samples и делает до10 minibatch epochs128.
В runner каждый1024-step цикл вызывается отдельно для точного учёта SGD;
среда/наблюдение сохраняются между вызовами. LR и clip schedules константны.
Это не изменение rollout length или частоты физического/мышечного управления.

Полный test не используется ни для промежуточной остановки, ни для выбора checkpoints.
Четыре диагностических задания пересекаются с test, но их результаты не входят
в критерии остановки и выбора модели.
После завершения freeze selection, строгая загрузка и native replay выбранных
validation; только затем test best/balanced_best/last. Набор уже известен
из предыдущих опытов, поэтому это не новый независимый benchmark.

## Запуск и артефакты

```bash
taskset -c 2 env OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 MKL_NUM_THREADS=1 \
  .venv/bin/python3 scripts/continue_arm_precision.py
```

Runner отказывается перезаписывать существующий `runs/arm_continuation/`.
В этом ignored каталоге остаются weights, metadata, summary с per-case validation,
per-rollout SGD/KL/value metrics, per-block stochastic probes и история остановки.
Core-модули с закреплёнными hashes не менялись. Новый полноценный D1, learned
release и анатомическая точность этим опытом не заявляются.

## Результаты

Остановлено после **49152 дополнительных переходов** и **1410 SGD-обновлений**:
выбран checkpoint **212992**, `runs/arm_continuation/best.zip`.
Причина — `validation_all_cases_passed`, а не плато. Первый блок завершён
полностью, второй остановлен после16384 переходов. Обучение вместе с validation
и промежуточными пробами заняло432,75 s на CPU; финальные проверки выполнялись
отдельно. Все результаты ниже относятся к исполнению средних команд без шума,
кроме явно обозначенных stochastic-проб.

| Этап | Переходов всего | Validation RMSE, ° | С равным весом целей, ° | Pass |
| --- | ---: | ---: | ---: | --- |
| Родитель | 163840 | 4,233 | 4,489 | 3/9 |
| Проверка | 172032 | 3,059 | 3,183 | 6/9 |
| Проверка | 180224 | 3,480 | 3,975 | 5/9 |
| Проверка | 188416 | 2,111 | 2,219 | 8/9 |
| Конец первого блока | 196608 | 3,053 | 3,505 | 6/9 |
| Проверка | 204800 | 2,866 | 3,202 | 6/9 |
| Выбранная модель | 212992 | **1,315** | **1,552** | **9/9** |

Кривая немонотонна: после8/9 следовали две проверки6/9, затем9/9.
Это показывает, почему одна неудачная проверка не была основанием прерывать
продолжение. KL-stop всё ещё сработал в40 из48 rollout-циклов; его наличие
само по себе не означает отсутствие обучения.

На полном test средняя tail RMSE снизилась **4,002→1,940°**, pass вырос
**4/11→10/11**, физических failures0. Критерий pass: не менее90% отсчётов

эпизод4 s завершается без failure. RMSE ниже усредняется по сценариям;

Все пять проверочных перемещений проходят. Время установления для них

стал1,204° вместо0,275°. Архивы `best`, `balanced_best`, `last` в итоге
содержат одинаковые обученные параметры.

### Средние команды и случайные выборки

На финальном checkpoint проверены те же четыре задания и два потока шума.
Здесь сравнивается tail RMSE, а не только итоговый угол.

| Задание, ° | Средняя команда, ° | Stochastic stream0, ° | Stream1, ° |
| --- | ---: | ---: | ---: |
| 20→75 | 0,527 | 3,088 | 1,785 |
| 75→20 | 1,539 | 2,046 | 1,596 |
| 25→105 | 2,074 | 0,838 | 3,050 |
| 60→60 | 1,245 | 2,414 | 2,656 |

Разрыва вида «средняя команда застревает внизу, случайные команды поднимают руку»
у этой модели на данных пробах нет. Случайное исполнение остаётся менее ровным;
по этим двум потокам нельзя заявить устойчивость ко всем возмущениям.

### Непрерывное демо

Проверен16-s headless-прогон без сброса между целями75→20→105→45°
(каждая по4 s). Все800 кадров v2 идут с шагом20 ms, failure нет.
RMSE за последнюю секунду каждого участка:0,527/1,496/2,744/0,100°.
Общая RMSE за16 s —21,60°: она включает большие ошибки сразу после смены цели.
GUI в этом запуске не открывался.

weights и rollouts остаются ignored.

### Вывод и ограничения

Для этого старта достаточно оказалось продолжить более устойчивую позднюю
оптимизацию: результат существенно улучшился без новых слоёв или предиктора.
Это не доказывает единственную причину прежних неудач и не означает полной
сходимости. Проверен один seed и знакомый набор задач, только постоянные цели;
слежение за синусоидой, новые нагрузки и длительное утомление здесь не оценены.
Триггер постоянно1; обучение отпусканию и защитному торможению в этот опыт
не входит. Дальнейшее обучение остановлено для просмотра модели пользователем.
