# Учебные состояния для удержания и переходов

Это завершённый диагностический опыт с persistent Beta. Он вышел на плато
первого этапа при 19136 actor-шагов; лучший блок прошёл 3/18 коротких удержаний.
Следующие этапы не достигнуты, полезная policy не получена. Фиксированная
память команды оставлена как исторический эксперимент, без биологического
обоснования; этот запуск не является рекомендуемым направлением обучения.

## Зачем изменён старт обучения

Исправление распределения возбуждений не дало полезного выполнения исходных
команд. Вариант Beta с одной эпохой PPO дошёл до плато на 117760 шагах: 0/12
движений и 0/6 проходов. Десять эпох улучшали общую оценку проходов, но после
176640 шагов номинальный подъём всё ещё заканчивался около 17.56° вместо 75°.

В исходном протоколе мышцы начинают с активацией 0.03. Рука быстро падает;
при начальных 75° команда на удержание действует лишь 0.5 s перед опусканием.
В отдельных двухсекундных стохастических пробах при 45°/75°/120° бонус
за установление был практически нулевым. После физической подготовки начального
состояния средний бонус составил 0.025–0.074. Это показывает отличие посещаемых
состояний, но не доказывает, что подготовка сама решает обучение. Отчёт:
`runs/d1_prepared_holding_probe.json`, скрипт сохранён рядом.

## Как готовится состояние

`PreparedProtocol.reset` сначала выполняет обычный reset, затем 2 s управляет
рукой через `baseline_action` и обычный `env.step`. Это диагностическая
эвристика только для подготовки. Она не формирует action-метки для обучения,
не вызывается после передачи управления и отсутствует в runtime обученной policy.

При передаче управления не переписываются q/qvel, мышцы, сухожилия, capacity,
очередь задержки, история или часы MuJoCo. Утомление за подготовку сохраняется:
1/0.8 — capacity перед подготовкой, не точное значение в момент передачи.
История содержит фактически применённые до этого возбуждения. Последующие
команды и конец эпизода сдвигаются по абсолютному времени; новая команда
по-прежнему открывается после оценки предшествующего действия.

Пробы подготовки не попадают в PPO buffer. `trained_steps` обозначает только
шаги управления actor; общий объём физической симуляции больше из-за подготовки.
На коротком первом этапе её цена существенна. Обучающий бонус вычисляется
прежним `result_reward`, без новой траектории или целевых мышечных возбуждений.

## Этапы

Используются seed 0, груз 1 kg, триггеры 0.3/0.6/1 и capacity до подготовки
1/0.8. Наборы полностью фиксированы.

1. Удержание 45°/75°/120° по 0.5 s после подготовки: 18 эпизодов.
2. Те же удержания по 2 s: проверка, что policy не живёт только за счёт начального тонуса.
3. Переходы ±10° к тем же трём целям за 4 s, команда меняется через 0.25 s: 36 эпизодов.
4. Прежние 18 упражнений compact с холодным стартом и без подготовки.

Policy, наблюдения, нормализация, задержки и физика между этапами одинаковы;
веса и Adam продолжаются, между этапами начинается новый физический эпизод.
На первом этапе обучение стартует с сохранённой начальной persistent Beta,
без обученных Gaussian-весов. Прямые мышечные выходы эвристики не являются
целями регрессии. Критик учится на результатах действий actor.

В каждом блоке собирается хотя бы один круг текущего набора, округлённый до
rollout 1472. Проверка — без шума с сохранением учебного RNG. Для первых этапов
требуются RMSE угла ≤3°, конечная ошибка ≤3°, RMS скорости ≤5°/s и реакция
нижнего ограничения ≤20 N·m во всех упражнениях; для переходов берётся
последняя секунда. Это инженерные критерии, не медицинские пороги.
После прохождения этапа или его плато выполняется также прежняя полная
**проверка с холодным стартом**. Только четвёртый этап может дать `demo_ready`.

Остановка этапа по плато — четыре блока без накопленного улучшения
max(0.5, 2% опорной оценки). Частичные успехи первых этапов нельзя выдавать
за управление оригинальными командами или за успешную защиту при release.
Отпускание trigger=0 в этом наборе пока не обучается.

## Запуск и артефакты

```bash
.venv/bin/python3 -m myo.train_holding --output-dir runs/d1_prepared_holding
```

Нужны локальная MyoArm, train-зависимости и
`runs/d1_bounded_persistent_beta/initial.zip` с metadata. Другой совместимый
persistent Beta задаётся через `--controller`; его происхождение сохраняется.
При продолжении собственного checkpoint также проверяется точный descriptor
учебных этапов и подготовки. Полное RNG/состояние среды из ZIP не восстанавливается.

Сохраняются `stage_*_block_*.zip` с v2 metadata, описанием подготовки/этапов,
результаты каждого учебного блока, отдельные cold-отчёты и `best_cold.zip`.
Поле `prepared_curriculum.source_sha256` задаёт исходник этого runner;
родительская metadata также сохраняет происхождение исходной bounded-policy.
`best_cold` выбирается только среди фактически выполненных полных cold-проверок,
а не по более лёгким учебным оценкам.

Регрессия сравнивает подготовку и передачу управления с непрерывным физическим
прогоном, проверяет сохранение истории/capacity и запрещает вызов эвристики
во время actor-шага. Результаты обучения — в [validation.md](validation.md).
