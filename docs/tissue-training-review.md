# Аудит параметров обучения предиктора

Аудит 2026-11-06 относится к [опыту с частотой ощущений](tissue-sampling.md),
а не к прежнему PPO. Обучается только предиктор, без actor, critic и reward.
Исходные trained checkpoints и код их обучения не менялись.

Самая конкретная найденная проблема — первый Adam-update после перехода
к BPTT: при сохранённом lr 0,001 он резко увеличивает ошибку на всей train
выборке. Эффект точно воспроизведён во всех 12 ветвях развёртки. Меньший lr
может устранить этот локальный скачок. Достаточность сети, оптимальность
learning rate и достижимый предел точности этим аудитом не установлены.

## Какие настройки фактически использовались

| Параметр | Значение |
| --- | --- |
| Оптимизатор | Adam, lr 0,001, betas 0,9/0,999, eps 1e−8 |
| Weight decay | 0 |
| Scheduler / разогрев learning rate | Нет |
| Batch | 128 окон, случайный выбор с возвращением |
| Начальная стадия | 1000 one-step updates |
| BPTT | До 2000 updates, без detach; 3/12/60 переходов для 20/5/1 ms |
| Состояние Adam при смене стадии | Сбрасывается; веса берутся из выбранного warm-up checkpoint |
| Gradient clipping | Общая L2-норма градиента до 10 |
| Инициализация | Стандартная `nn.Linear`, последний линейный слой обнулён |
| Начальный прогноз | Текущее ощущение плюс среднее train-приращение |
| Вход | Замороженные train mean/STD, нижний предел STD 1e−5 |
| Масштаб выхода / one-step loss | Train STD приращений своего шага, нижний предел 1e−6 |
| BPTT loss | MSE всех ощущений в общих точках 20/40/60 ms, масштаб STD приращений за 20 ms |
| Проверка и сохранение best | Update 1, затем каждые 200 и на последнем update |
| Выбор warm-up | Ошибка четырёх длин через 20 ms; для короткого шага это уже собственная развёртка |
| Выбор BPTT | Средний нормированный RMSE четырёх длин на 20/60 ms |
| Остановка BPTT | Не ранее 1000, отсутствие значимого улучшения на 1% за 600 updates |
| Seed | Один, 0; отдельных подборов optimizer по шагам не было |

Значения Adam совпадают с дефолтами установленной версии; это не свидетельство
их оптимальности для данного предиктора. Описание параметров:
[Adam](https://docs.pytorch.org/docs/stable/generated/torch.optim.Adam.html),
[clip_grad_norm_](https://docs.pytorch.org/docs/stable/generated/torch.nn.utils.clip_grad_norm_.html).

## Первый update BPTT слишком велик

Для каждой ветви восстановлены выбранные warm-up веса и **точно тот же первый
minibatch**, что в исходном обучении: batch 128 и генератор с seed 0. Создаётся
новый Adam, как в исходном коде, и выполняется один update на копии модели.
При lr 0,001 воспроизведены сохранённые validation score и норма градиента;
допуск проверки 1e−6 относительный. Затем та же локальная проверка повторена
с четырьмя меньшими learning rate. Диагностические веса не сохраняются как
новые модели, test-выборка для сравнения learning rate не используется.

Полная механика, шаг предиктора/ощущений 1 ms:

| Состояние | Loss на всей train-выборке | Validation score на 20/60 ms |
| --- | ---: | ---: |
| До update | 0,06210 | 0,49518 |
| После update, lr 0,001 | **7,38660** | **2,72564** |
| lr 0,0003 | 0,72590 | 0,94248 |
| lr 0,0001 | 0,09398 | 0,52792 |
| lr 0,00003 | **0,05045** | **0,48330** |
| lr 0,00001 | 0,05616 | 0,48911 |

Loss здесь — фактическая BPTT MSE шести каналов в 20/40/60 ms, а score —
описанный выше критерий длин. При исходном lr полная train loss возрастает
примерно в **119 раз** за один update, а норма изменения всех параметров
относительно исходной нормы весов составляет **2,08%**. Норма градиента 3,73,
то есть clipping вообще не срабатывает. Даже уменьшение lr в 10 раз в этой
точке недостаточно; 3e−5 улучшает и train loss, и validation score.

В полной механике при шагах 20/5 ms исходный первый update увеличивает
полную train loss соответственно 0,01684 → 0,41544 и 0,03251 → 1,21858.
При lr 3e−5 она уменьшается до 0,01606 / 0,02876; validation score также
уменьшается. Это сильное основание проверить более мягкий переход к BPTT,
но не доказательство, что постоянный lr 3e−5 окажется лучшим после тысяч
обновлений. Вклад сброса моментов Adam отдельно от смены loss и lr не изолирован.

Порог clipping не является ограничением изменения весов или будущего прогноза.
Из **121 сохранённой проверки** BPTT норма превысила 10 только в одной.
Это наблюдения каждые 200 updates, а не частота clipping на всех updates.
Гипотеза о постоянном подавлении градиента этим порогом не подтверждена.

## Одинаковые updates не означают одинаковый объём warm-up

| Шаг перехода | Разных train-окон | Предъявлений за 1000 updates | Эквивалентных проходов |
| --- | ---: | ---: | ---: |
| 20 ms | 2400 | 128000 | 53,33 |
| 5 ms | 9600 | 128000 | 13,33 |
| 1 ms | 48000 | 128000 | 2,67 |

Это арифметика с выборкой с возвращением, не буквальные эпохи. Соседние fine
окна сильно коррелированы; уравнивать число проходов любой ценой не требуется.
Но считать фиксированные 1000 updates одинаково достаточной подготовкой
для всех ветвей нельзя. В BPTT общие 2388 train-окон; различие выше относится
именно к подготовительной стадии.

В аудите отдельно измерена validation-ошибка одного native-перехода по
истинной прошлой истории **на всех фазах внутри команды**. Для полной
механики MSE, нормированная STD собственного приращения:

| Шаг | Выбранный warm-up | Выбранный BPTT |
| --- | ---: | ---: |
| 20 ms | 0,04246 | 0,02687 |
| 5 ms | 0,06992 | 0,04521 |
| 1 ms | 0,20108 | 0,20988 |

В последней ветви BPTT не улучшил локальную точность, хотя уменьшил ошибку
развёртки относительно warm-up. В остальных 11 ветвях native one-step MSE
после выбранного BPTT ниже, чем после выбранного warm-up. Общего разрушения
одношаговой динамики не обнаружено. Сравнение между временными шагами требует
учёта того, что знаменатель STD у каждого свой.

Нужно различать native one-step validation и свободную развёртку: в исходных
логах для 1/5 ms warm-up сохранялась преимущественно ошибка развёртки на 20 ms,
а не полная диагностическая картина самого короткого перехода.

## Функция ошибки имеет существенные неявные веса

Нормировка на STD делает шкалы сопоставимыми относительно данных. Она не
означает одинаковую цену одинаковой ошибки в метрах. В полной механике
STD приращений за 20 ms соответствует:

- Волокно: **0,8552 / 0,8532 mm** для верхней/нижней мышцы.
- Сухожилие: **0,02995 / 0,02980 mm**.
- Активация: **0,006908 / 0,005901**.

При одинаковой абсолютной ошибке длины вклад одного сухожильного канала
в квадрат ошибки приблизительно в **815–820 раз** больше вклада волоконного.
Это может быть оправдано большей жёсткостью сухожилия и меньшим характерным
изменением длины, но такое соотношение — решение о цели оптимизации,
а не нейтральное преобразование единиц.

У выбранных BPTT-моделей полной механики доли фактической validation loss
в общих точках 20/40/60 ms:

| Шаг | Волокна | Сухожилия | Активации |
| --- | ---: | ---: | ---: |
| 20 ms | 22,90% | 32,94% | **44,17%** |
| 5 ms | **42,09%** | 24,33% | 33,58% |
| 1 ms | 17,26% | 38,54% | **44,20%** |

Обучение минимизирует все шесть каналов и включает 40 ms. Критерий выбора
исключает активации и точку 40 ms и усредняет RMSE, а не MSE. Такая
вспомогательная loss допустима, но её смысл и вес должны быть явными:
выбранный checkpoint не обязан быть лучшим по полной учебной цели.
Физическая точность будущих активаций тоже нужна последующим переходам.

## Входы и насыщение Tanh

Измерения сделаны на собственных validation-развёртках выбранных BPTT-моделей
до 60 ms. Насыщенным считается значение `abs(h)>0.99`.

| Шаг | Насыщено в первом Tanh | Во втором Tanh | Средняя производная первого/второго |
| --- | ---: | ---: | ---: |
| 20 ms | 1,37% | 0,51% | 0,826 / 0,682 |
| 5 ms | 1,15% | 0,48% | 0,831 / 0,686 |
| 1 ms | **16,21%** | **5,56%** | 0,560 / 0,444 |

Рост насыщения у 1 ms измерен, однако полного коллапса производных нет.
Причинная роль Tanh по сравнению с другими функциями этим аудитом не проверена.

Отдельно рассмотрен спектр ковариации стандартизированных train-входов на
480 общих контрольных началах. В полной механике 99% дисперсии объясняют
четыре линейные компоненты при всех трёх частотах, несмотря на 26/80/368
входов. Это свидетельство сильной коррелированности кадров, а **не основание
выбрасывать остальные компоненты**: малые временные разности несут информацию
о скорости. Нормировать абсолютные кадры отдельно недостаточно, чтобы сделать
эти разности удобными для обучения. Следует проверить их явное представление.

## Обобщение и остановка

В полной механике общая нормированная MSE выбранной BPTT-модели:

| Шаг | Фиксированная train-выборка | Validation |
| --- | ---: | ---: |
| 20 ms | 0,004452 | 0,051197 |
| 5 ms | 0,004762 | 0,047135 |
| 1 ms | 0,016470 | 0,304215 |

И после выбранного best train tracking score продолжает уменьшаться, тогда
как validation score ухудшается. Это разрыв между подгонкой и обобщением,
а не свидетельство, что достаточно просто дать всем ветвям больше updates.
Новые близкие соседние окна не заменяют разнообразие физических эпизодов.

600 updates patience при проверке раз в 200 — три периода без значимого
улучшения. До остановки lr не уменьшается. Значит, `validation_plateau`
устанавливает отсутствие прогресса при текущем режиме оптимизации,
но не исчерпание возможностей сети. Проверка раз в 200 также даёт только
шесть оценок за warm-up и может пропускать промежуточные лучшие веса.

## Приоритет следующего опыта

1. Изолировать learning rate: на прежней сети и тех же данных проверить
   меньший начальный шаг BPTT и его снижение при остановке прогресса.
   Локальная проба обосновывает проверку 1e−4 и 3e−5, не назначает победителя.
2. Логировать native one-step validation, свободную развёртку и вклад каждой
   группы каналов. Согласовать основной критерий выбора с целью обучения;
   явно определить вспомогательный вес активаций и требования к точности тканей.
3. Оценивать достаточность warm-up по его кривой, а не общему числу updates.
   Не увеличивать число почти одинаковых окон ради формального равенства эпох.
4. После этого отдельно сравнить Tanh/SiLU/LeakyReLU и размеры сети,
   не менять все параметры одновременно. Явные причинные разности ощущений —
   отдельная абляция представления, не результат уже выполненного опыта.

Корректные части протокола сохраняются: нормировка только на train,
разделение целыми эпизодами, собственная история внутри BPTT, точная внешняя
очередь задержки, общие физические моменты сравнения и отсутствие test в
выборе checkpoint. Новое длительное обучение в рамках аудита не проводилось.

## Воспроизведение

```bash
.venv/bin/python3 scripts/audit_tissue_training.py > runs/tissue_training_audit.log 2>&1
.venv/bin/python3 -m py_compile scripts/audit_tissue_training.py
```

Результат — `runs/tissue_sampling/training_audit.json`, status `passed`.
Скрипт проверяет идентичность данных/весов/источников, читает журнал,
пересчитывает ошибки и статистику скрытых слоёв и точно воспроизводит первый
update каждой из 12 ветвей BPTT. Затем сравнивает пять learning rate на копиях.
Обученные checkpoints не перезаписываются. Регулярные unit-тесты не добавлены:
это диагностика сохранённых экспериментов, а не изменение динамики или runtime.
