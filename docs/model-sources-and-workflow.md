# Источники моделей и стратегия разработки

Согласовано **2026-10-31**. Это выбранная стратегия, а не отчёт об импорте:
в коде пока работает собственная V0. MyoArm, анатомические меши, UE-проект и
Flesh assets ещё не интегрированы. Целевое поведение описано в
[first-stage.md](first-stage.md), визуальные шаги — в
[плане интеграции UE](../integrations/unreal/README.md).

## 1. Откуда берём модель для физики

Основной источник — **MyoArm из MyoSim**, библиотеки моделей экосистемы MyoSuite.
Берём модель тела, а не обязательно готовую среду или весь процесс обучения MyoSuite.
Собственные команды угла/триггера, историю наблюдений и PPO можно сохранить.

| Данные | Источник и назначение |
| --- | --- |
| Скелет, суставы, исходные положения костей | MyoArm: основа механической руки |
| Мышцы и их именованные приводы | MyoArm: номенклатура и выбор мышц, действующих на локоть |
| Начала, прикрепления, промежуточные точки и огибания | Мышечно-сухожильные пути MyoArm для расчёта длин и плеч моментов |
| Силовые параметры и рабочие диапазоны длин | Параметры приводов MyoArm как исходная модель, не индивидуальные измерения человека |
| Геометрия костей | Меши MyoArm; используем те же формы и преобразования для изображения |

Первичные источники: [MyoSim](https://github.com/MyoHub/myo_sim),
[MyoArm](https://github.com/MyoHub/myo_sim/blob/main/myo_sim/models/arm/README.md),
[XML-компоненты](https://github.com/MyoHub/myo_sim/tree/main/myo_sim/models/arm/assets).
Точные upstream commit и состав файлов фиксируем при импорте; автоматически
обновлять модель с движущейся ветки `main` во время эксперимента нельзя.

Для первого этапа оставляем сгибание локтя, остальные движения фиксируем.
Сохраняем необходимые участки плечевого пояса и геометрию проксимальных
прикреплений даже при неподвижных костях. Не заменяем путь мышцы прямой линией
только ради простоты рисунка. Отрисовка и механика используют общие прикрепления.
MyoElbow можно использовать для сравнения, но основа целевой руки — MyoArm.

**Упругие сухожилия не считаем готовой возможностью импортированной модели.**
Штатная мышца MuJoCo предполагает нерастяжимое биологическое сухожилие;
`spatial tendon` задаёт путь, а не самостоятельную последовательную упругость.
См. [MuJoCo: Muscles](https://mujoco.readthedocs.io/en/stable/modeling.html#muscles).
Сохраняем или реализуем согласованный привод с отдельными длинами волокна и
сухожилия, моторной задержкой, активацией и capacity. Силовые коэффициенты нельзя
слепо переносить между разными законами мышцы. При замене штатного привода
исключаем двойное приложение сил и проверяем рабочие длины, моменты и торможение.
Пассивное сопротивление локтя у предела также настраивается отдельно.

## 2. Откуда берём меши для изображения

**Кости — из той же MyoArm. Формы мышечных брюшек — из официального BodyParts3D.**
Это не готовая согласованная пара моделей: масштабы, позу и мягкие ткани нужно
привести к механическому скелету, сохранив выбранные точки прикрепления.

- [BodyParts3D: загрузка](https://dbarchive.biosciencedbc.jp/en/bodyparts3d/download.html)
  предоставляет OBJ и таблицы анатомических названий/идентификаторов.
- Условия [официального источника](https://dbarchive.biosciencedbc.jp/en/bodyparts3d/lic.html)
  обновлены 2025-02-27: **CC BY 4.0**, без ShareAlike. Берём данные оттуда,
  а не из зеркала или производного проекта с другой лицензией.
- Подготовленные для симуляции сухожильные объёмы для каждой мышцы пока не
  подтверждены. Их выделение или построение — часть подготовки наших assets.

Последовательность: выбрать нужные мышцы → согласовать с костями/путями MyoArm →
проверить и исправить поверхность → разметить области прикрепления, волокна и
сухожилия → создать тетраэдральный объём и настроить активное сокращение Flesh.
Готовые OBJ не объявляем замкнутыми или пригодными к тетраэдрализации до проверки.
Пути привода не являются объёмными мешами, а конвертация STL/OBJ не создаёт риг.
Для первой руки допустим открытый вид мышц без кожи и жира.

**Z-Anatomy не используем как источник встраиваемых UE-мешей по умолчанию.**
Его [README](https://github.com/Z-Anatomy/Models-of-human-anatomy/blob/master/Readme.md)
указывает CC BY-SA 4.0, а [Unreal EULA, §6(c)](https://www.unrealengine.com/eula/unreal)
перечисляет Attribution-ShareAlike среди несовместимых лицензий. Открытость нашего
кода или некоммерческий статус сами по себе это не разрешают. Изменённые меши
Z-Anatomy нельзя переобозначить как CC BY только из-за происхождения из BodyParts3D.
Иной путь требует отдельного подходящего разрешения; сейчас он не выбран.

[Официальный tutorial Chaos Flesh с Emil](https://dev.epicgames.com/community/learning/tutorials/RZwB/unreal-engine-chaos-flesh-muscle-simulation-tutorial-5-6)
используем как технический пример настройки, не как анатомическую основу MyoArm.
Его assets не переносим в публичный репозиторий без проверки условий конкретной
поставки. Подготовка нашей руки и соответствие её параметров всё равно необходимы.
См. также [Chaos Flesh Quickstart](https://dev.epicgames.com/documentation/unreal-engine/chaos-flesh-quickstart).

## 3. Происхождение и лицензии

При импорте сохраняем источник, версию/commit, контрольную сумму, лицензию,
необходимые уведомления и описание изменений для каждого набора. Отдельно
фиксируем соответствие имён мышц, систему координат, масштаб и преобразование
исходной позы. Исходные файлы отделяем от наших производных и сгенерированных кэшей.

У MyoSim верхнеуровневая лицензия Apache 2.0, но происхождение модели руки от
MoBL-ARMS требует отдельного учёта. В
[NOTICE MuscleMimic Models](https://github.com/amathislab/musclemimic_models/blob/main/NOTICE)
для исходной MoBL-ARMS указано ограничение некоммерческого использования,
включающее разрешённое personal use. Перед включением файлов проверяем условия
самого выбранного upstream-пакета; общий badge Apache не заменяет эту проверку.
Продажа будущего продукта потребует отдельной оценки прав на эти компоненты.

Для BodyParts3D сохраняем требуемое указание авторства:
«BodyParts3D, © The Database Center for Life Science licensed under CC Attribution 4.0 International».
Указываем ссылку на лицензию и наши изменения. Новые условия BodyParts3D не
переоформляют автоматически чужие производные модели.

В этой правке сторонние модели и меши не загружаем и не публикуем. До проверки
прав в GitHub храним ссылки, инструкции и собственный код подготовки, а не
перезаливаем все архивы. Лицензия нашего кода отдельно выбирается владельцем;
см. [licenses.md](licenses.md). Эта стратегия не является юридическим заключением.

## 4. Где ведём разработку

**Первое время работаем локально на Ubuntu-ноутбуке ThinkPad со встроенной графикой.**
Здесь разрабатываем механику, управление, историю, небольшое обучение и простой
MuJoCo-viewer. UE и Chaos Flesh на ноутбук заранее не устанавливаем. Достаточность
его производительности оцениваем по фактическим запускам, а не обещаем FPS.

| Стадия | Рабочая машина | Условие перехода |
| --- | --- | --- |
| Механика руки, MyoArm, первый контроллер, диагностический вид | Локальный Ubuntu-ноутбук | Основное место работы, пока скорость экспериментов удобна |
| Подробная визуализация, UE, Chaos Flesh или более тяжёлая модель | Локальный Windows-десктоп с RTX 3060 | Понадобился UE либо ноутбук перестал справляться |
| Масштабное обучение полного тела и многих движений | Облачный GPU-сервер, только при необходимости | Измеренное время/память на десктопе уже неприемлемы; есть подходящий бэкенд |

При переходе просто переносим разработку за десктоп через GitHub и локальные
артефакты. **Не строим сейчас Remote Desktop, streaming, постоянный Remote SSH
между ноутбуком и десктопом или распределённый цикл физики.** WSL2 не обязательная
зависимость: способ запуска Python на Windows выбираем и проверяем при переходе.
Физика, контроллер и графика полного демо по умолчанию работают на одной машине.
Обучение остаётся независимым от UE; текущая виртуалка чата не является целевой
машиной для проверки Unreal или окончательным местом хранения результатов.

Облако — поздняя возможность, прежде всего для headless-обучения: локально
проверить небольшой опыт → выполнить большой запуск на сервере → вернуть веса
и результаты → проверить демо локально. Remote Desktop нужен только при отдельной
необходимости удалённых графических инструментов. Провайдера и тариф сейчас не
выбираем, сервер не арендуем и ничего не разворачиваем.

Мощный GPU сам по себе не ускоряет последовательную CPU-физику и маленькую MLP.
Перед облаком измеряем узкое место и проверяем параллельный бэкенд на десктопе.
Перенос не должен терять упругие сухожилия, задержки или менять семантику модели.
См. [бюджет runtime](runtime.md),
[PPO: CPU/GPU](https://stable-baselines3.readthedocs.io/en/master/modules/ppo.html),
[MuJoCo Warp](https://mujoco.readthedocs.io/en/stable/mjwarp/index.html).

## 5. Минимальная переносимость без новой инфраструктуры

Храним в GitHub исходники, конфигурации, версии и документацию. `.venv`, кэши,
тяжёлые результаты и чужие assets не превращаем в общую сетевую рабочую папку.
С весами сохраняем конфигурацию тела, порядок/нормализацию наблюдений, историю,
периоды управления и физики, параметры задержки и идентичность предиктора.
Для будущих длительных запусков отдельно понадобится проверенное возобновление
обучения с нужным состоянием алгоритма; наличие файла policy само это не доказывает.

Ближайшая реализация — подготовка ограниченной по движениям MyoArm и согласованного
диагностического изображения на ноутбуке. UE подключаем после стабилизации
геометрии и интерфейса состояния, не ожидая завершения всех опытов обучения;
Flesh — для объёмной деформации, ML Deformer — только по измеренной необходимости.
