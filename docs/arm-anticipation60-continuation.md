# Продолжение предиктора60 ms с увеличенным бюджетом

Протокол от **2026-11-09**, по запросу владельца после
[первых150000 updates](arm-anticipation60.md). Меняем только доступный бюджет.
PPO, архитектура33→4×128 + conditioned head134→128→20, данные, split,
loss, sampling, нормировки и RMSprop LR1e−4 остаются прежними.

## Возобновление

Родитель —`runs/arm_anticipation60/last.pt`,150000 updates.
В этой точке last совпал с best. Восстанавливаются все параметры/buffers,
полный RMSprop state/paramgroups и исходная последовательность minibatch-примеров.

Старый checkpoint не сохранял RNG. NumPy-поток восстанавливается из seed0
пропуском150000×128 прежних double-выборок; Torch-поток —исходным seed
и тем же конструктором. В этой сети нет dropout/стохастических слоёв,
а при обучении Torch RNG расходовался только на инициализацию модели.
Новый behavioral test сравнивает непрерывный update с сохранением/reload:
совпадают следующие draws, начальные optimizer moments, веса после update
и Torch RNG. Это проверка конкретного текущего trainer, не универсальный resume API.

Перед продолжением повторно проверяются train-only mean/STD,
dataset hash и sampling cells. Исходный checkpoint/dataset не перезаписываются.
Все новые артефакты —`runs/arm_anticipation60_extended/`.

## Бюджет и выбор модели

До**300000 дополнительных updates**, общий максимум**450000**.
Validation каждые1000; best по минимуму balanced MSE всех validation-окон,
включая исходную модель. Сохраняется прежний progress reference:
его история восстанавливается из старого training.json.
Без накопленного улучшения0,5% за20000 updates —остановка по тому же правилу.
Если достигнут450000 при продолжающемся улучшении, это бюджетная остановка,
не доказанное плато.

Архив initial фиксирует исходные веса и RMSprop moments в новом каталоге;
best/last и metadata хранят источник, исходный hash, общий номер updates
и параметры продолжения. История графика включает первые150000 updates,
но elapsed_s нового запуска считает только продолжение.

До test фиксируется hash best и проверяется строгий reload/replay validation.
На общих test-окнах сравниваются новый direct, direct150k, старый one-step×3
и persistence. После выбора повторяются те же16 пар команд и прогоны актуальных
контроллеров. Их метки остаются только оценкой, в train не добавляются.
Test исторический и уже известен; новая проверка не является независимым benchmark.

```bash
taskset -c 2 env OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 MKL_NUM_THREADS=1 \
  .venv/bin/python3 scripts/continue_arm_anticipation.py
taskset -c 2 env OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 MKL_NUM_THREADS=1 \
  PYTHONPATH=/tmp/myo-supervised-plot-deps MPLCONFIGDIR=/tmp/myo-supervised-mpl \
  .venv/bin/python3 scripts/report_arm_anticipation.py \
  --root runs/arm_anticipation60_extended --diagnostics --plot
```

## Результаты

Выполнены все**300000 дополнительных updates**, общий номер450000.
Best —**448000**, `runs/arm_anticipation60_extended/best.pt`.
Продолжение с validation заняло**574,43 s** CPU; первоначальный этап —335,22 s.
Это повторные minibatch-обновления на том же наборе66726 train-окон,
а не дополнительные физические эпизоды. Learning rate не менялся.

Остановка —`maximum_updates`. На448000 произошло новое значимое улучшение,
поэтому **критерий плато не сработал**. Максимальный бюджет не был продлён
после открытия test или причинных проб.

| Метрика выбора | 150000 | Best448000 |
| --- | ---: | ---: |
| Train balanced MSE, фиксированные8192 окна | 0,023055 | 0,005690 |
| Validation balanced MSE, все27522 окна | 0,027753 | 0,009601 |

Validation MSE уменьшилась на**65,4%**. Разрыв с train вырос, но обе ошибки
снижались к концу. Сам по себе этот разрыв не доказывает остановку обобщения.
Last450000 имел validation0,011299, поэтому оценивается выбранный best448000.

| Все28710 окон | 0,1559 | **0,1009** | 3,441 | **2,229** |
| hold | 0,1072 | 0,0362 | 3,077 | 1,388 |
| ramp | 0,1143 | 0,0499 | 2,147 | 1,537 |
| jitter | 0,1368 | 0,0908 | 3,651 | 2,274 |

Общая RMSE угла/скорости ниже примерно на**35%**; улучшение есть во всех
семействах. Прежний одношаговый predictor×3 на тех же окнах даёт0,1800°/3,999°/s.
Прогноз448k по этим двум общим метрикам лучше и150k, и старого×3.

Ошибка0,1009° равна4,66% RMS реального изменения угла за60 ms и13,76%
изменения за20 ms. Ошибка скорости2,229°/s —10,62% и25,53% соответственно.
Это отношения RMS по выборке; не покадровое деление на почти нулевое изменение.

По активациям RMSE уменьшилась с0,00855–0,00956 до**0,00405–0,00432**
от диапазона0…1, примерно с0,9 до0,4 процентного пункта.
Прежний×3 имеет0,00132–0,00417 и по большинству мышц ещё точнее.
Ошибки относительных длин волокон теперь0,000428–0,001302 оптимальной длины,
capacity proxy —около0,0000043–0,0000063. Полная таблица20 каналов —
`budget_comparison.md`/`.json`; большая точность этих proxy не является
проверкой физиологической калибровки.

### Актуальные policy и отклик на команду

Повторены те же11 задач каждого из двух неизменённых контроллеров.
По2178 окон на policy, модели/начальные условия совпали; persistence-метрики
и identities проверены на точное совпадение с первым опытом.
Веса этих контроллеров не обновлялись.

| Источник | Угол150k, ° | Угол448k, ° | Скорость150k, °/s | Скорость448k, °/s |
| --- | ---: | ---: | ---: | ---: |
| Успешный none | 0,2080 | **0,0910** | 5,597 | **3,081** |
| Frozen lower-LR | 0,1827 | **0,0699** | 5,708 | **2,752** |

На успешном none старый×3 даёт0,1248°/3,127°/s: новый448k лучше по углу,
по скорости почти паритет. На frozen старый×3 даёт0,0906°/1,947°/s:
новый448k лучше по углу, но **хуже по скорости**.

Для командных контрастов проверено побитовое совпадение исходных33 входов,
команд и реальных исходов32 native-ветвей с прежним опытом.
RMS реального эффекта0,1852°/26,028°/s. Ошибка прогнозируемого эффекта скорости
снизилась с34,9% до24,4% его RMS. Старый×3 точнее по этому показателю:
3,367°/s,12,9% эффекта. По положению он хуже:0,2051° против новых0,0666°.
Знак эффекта скорости верен во всех16 пробах у обеих моделей; это не проверка
всех направлений действий и не гарантия корректного Jacobian.

### Вывод

Увеличенный бюджет дал существенное улучшение при прежних данных и LR,
включая прогноз актуальных контроллеров. Ограничение150000 updates было
существенным фактором качества первого прямого предиктора.
Это не доказывает, что дополнительный бюджет решит все остаточные ошибки:
по отклику скорости на команду и по части ощущений старый×3 ещё лучше.

Плато пока не установлено. Best448k сохранён для следующего опыта;
PPO с его frozen-кодировщиком **не обучался**, польза представления для
контроллера отдельно не доказана. Схема двух представлений остаётся прежней:
фиксированный encoder предиктора плюс обучаемые private-ветви actor/critic.

### Проверки и артефакты

Optimizer step counters: initial150000, best448000, last450000.
Сохранённый старый150k заново воспроизвёл все прежние test-метрики точно.
