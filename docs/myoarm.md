Источник — [MyoHub/myo_sim](https://github.com/MyoHub/myo_sim), закреплённый commit
`93b0ca8f4ec90c9899ee7f05fee561e9911da91b` (v0.2.3). Исходные XML и STL
загружаются только в игнорируемый `data/myoarm/upstream`; в репозиторий они
не включаются. На каждый файл сохраняются URL, Git blob SHA-1 и SHA-256.

Скелет, исходные массы, mesh transforms, attachment sites и wrap геометрии
берём из одной версии MyoArm. Производная XML хранится отдельно от исходников.
BodyParts3D, поверхность кожи и UE/Flesh assets этот импорт не создаёт.

## Запуск

После `bash scripts/setup.sh`:

```bash
.venv/bin/python3 scripts/prepare_myoarm.py
.venv/bin/python3 -m pytest -q tests/test_myoarm_geometry.py
```

Первый запуск скачивает 39 файлов (~7 MB) с публичного GitHub. Каждый файл
проверяется по закреплённому Git blob hash; повторный запуск использует уже
проверенные локальные файлы. `preparation-plan.json` записывает происхождение и
лицензии каждого файла до загрузки. Успешный `manifest.json` атомарно записывается
после подготовки и содержит SHA-256 всех источников и производных `model.xml`,
`muscles.json`; неудачная повторная загрузка не стирает последний успешный manifest.
При исполнении проверяются их контрольные суммы: изменение геометрии не может
незаметно сохранить идентичность модели обученного checkpoint.

`MyoArmGeometry` предоставляет готовый `MjModel`, имена мышц, начальные параметры,
длины пространственных сухожильных путей, плечи `-dL/dq`, точки креплений и касания
wrap-геометрии. Для кривых участков рисунок использует native tendon renderer
MuJoCo; соединение касательных точек прямой хордой не воспроизводит путь.

## Упрощения и диапазон модели

- Подвижен только `elbow`; остальные 37 суставов удалены при исходном `q=0`.
  Плечевой пояс и проксимальные прикрепления сохранены. Поза фиксированного плеча
  пока является конфигурацией стенда, не подгонкой человека или позой из motion capture.
- Оставлены пути `BIClong`, `BICshort`, `BRA`, `TRIlong`, `TRIlat`, `TRImed`.
  Полного набора мышц локтя здесь нет: например, brachioradialis не управляется.
- Все штатные приводы удалены; `model.nu == 0`, stiffness/damping пространственных
  сухожилий равны нулю. Сила поступает единственным путём через собственные
  series-elastic muscles; geometric tendon не объявляется упругим сухожилием.
- Нижний предел локтя — 15°; верхний предел снят (`+inf`). Верхнего численного
  упора и мягкой пружины при 130° нет. Нижнее мягкое сопротивление и задержки
  задаёт среда отдельно. Команда пользователя также не обрезается сверху.
  Массивный груз жёстко закреплён в системе кисти, не меняет массу при отпускании.
- Сохраняются исходные локальные координаты в метрах. Явный mount поворачивает
  Y-up исходник в Z-up стенд с наклоном плеча вперёд на 30°. Это преобразование
  всей физической модели; будущий renderer boundary должен отдельно переводить SI
  и оси в соглашения Unreal. Коллизии геометрии руки отключены для данного стенда.

Из штатных приводов переносим `F_max`, нормировку длины и соответствующие
рабочие длины, а не весь закон силы. Для MuJoCo `gainprm[:2] = [a,b]` и
`lengthrange = [L_min,L_max]`:

```text
L_opt = (L_max - L_min) / (b - a)
L_slack = L_min - a * L_opt
F_max = gainprm[2]
```

Отдельные compliance, моторная задержка, активация, ограничение силы при
удлинении и capacity принадлежат нашей приближённой мышце. В `muscles.json`
сохранены исходные `gainprm` и `lengthrange` для проверки преобразования.
Перенос не доказывает эквивалентность динамики MyoSuite или анатомическую точность.

В конфигурациях D1 теперь выполнена [предварительная калибровка](calibration.md):
ширина force–length `0.7949003` согласует свежую кривую момента с исходным
приводом на 15–130°, а независимый активный масштаб сгибателей `1.3692387`
задаёт предварительный мужской ориентир силы при 90°. Исходный `F_max`,
жёсткость сухожилия и пассивная упругость этим масштабом не изменяются.
Коэффициенты утомления/восстановления перенесены из опубликованных локтевых
экспериментов; параметры не подогнаны под каждого человека или каждую мышцу.

За 130° исходные пути используются как экстраполяция. После **161.546°**
плечи всех трёх головок трицепса меняют знак: это ограничение геометрической
модели, а не поведение человеческого трицепса. При 1 kg знак суммарного
гравитационного момента меняется около 146.113°, а необходимого активного
момента с учётом пассивных тканей — около 153.490°. Проверяем переход до
этой области отдельно; возможность задать 175° не означает анатомическую
достоверность такой позы. Конечный охват учебных целей до 158° не вводит
новый физический ограничитель.

После изменения подготовки модели повторно запустите `scripts/prepare_myoarm.py`:
проверенные локальные источники будут переиспользованы. Обновлённый manifest
и физика несовместимы со старыми checkpoints, включая `d1_actor_corrected.zip`;
проверка идентичности при загрузке сохраняется.

## Проверки

Исторический прогон до снятия верхнего предела:
`python3 -m pytest -q tests/test_myoarm_geometry.py`: **7 passed** на подготовленных
assets. Производные длин проверялись при 15°, 45°, 75°, 105°, 129°; сравнивались
точки изображения и physical attachment sites, единственность силового пути
и жёсткая связь груза с кистью. Проверена headless EGL-отрисовка костей и путей
при 75°; наличие изображения не подтверждает естественность движения или GUI.
Новые регрессии проверяют отсутствие верхней реакции/пружины, конечные
наблюдения при неограниченном суставе и явное сообщение о смене знака пути.
Фактические результаты актуального набора и сводные проверки всей среды
записываются в [validation.md](validation.md).

При отсутствии локальных assets эти интеграционные тесты явно пропускаются.
Обычный тестовый прогон ничего не скачивает и не принимает сторонние лицензии.
