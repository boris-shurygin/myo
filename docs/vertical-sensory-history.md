# История ощущений в минимальном вертикальном предикторе

Следующее выполненное сравнение — [рекуррентный резервуар вместо явного окна](vertical-reservoir.md).
После него выполнено сокращение явного окна до **60 ms**; результаты ниже.
Затем по решению владельца предиктор переведён на
[локальные ощущения мышц/сухожилий и их производные](tissue-predictor.md),
без глобальных координат во входах и целях.

Сравнение с [исходным стендом](vertical-predictor.md): помогает ли 200 ms
прошлых ощущений предсказывать движение при уже доступном текущем внутреннем
состоянии мышцы. Обучается только предиктор; моторные команды даёт прежняя
эвристика. Новый контроллер и восстановление скрытой активации здесь не учатся.

## Постановка сравнения

Две ветви обучаются с нуля для каждой из четырёх механик:

- `current`: прежние физические входы и дошедшая команда;
- `sensory_history`: те же входы плюс десять предыдущих физических кадров,
  от 20 до 200 ms назад, от нового к старому.

Кадр содержит положение, скорость и, по варианту механики, длины волокон
и активации. История возбуждений не добавляется. Транспортная очередь остаётся
отдельной, сдвигается точно; MLP получает только команду ближайшего интервала.
Это история состояний симулятора, не доказательство их биологической измеримости.
На reset прошлое заполняется начальным кадром только своего эпизода.

| Механика | Физических каналов | Вход без истории | Вход с историей |
| --- | ---: | ---: | ---: |
| 1 | 2 | 4 | 24 |
| 2 | 4 | 6 | 46 |
| 3 | 4 | 6 | 46 |
| 4 | 6 | 8 | 68 |

Скрытые слои везде `128 Tanh → 128 Tanh`, выход — физические приращения.
При добавлении истории общие начальные веса сохраняются, её столбцы первого
слоя инициализированы нулями: начальные функции ветвей одинаковы.
Количество параметров с историей возрастает из-за расширения первого слоя;
это не сравнение при строго равном числе параметров.

Берутся существующие `episodes.npz` без пересбора физики: 6 train,
3 validation, 3 test эпизода по 8 s на механику. Split задан целыми эпизодами
до добавления истории; его состав и SHA256 данных записаны в `summary.json`.
Текущие активации и длины остаются входами: это проверка дополнительной истории,
а не её способности заменить недоступное внутреннее состояние.

Как в исходном запуске: seed 0, Adam 0,001, batch 128, clip 10,
1000 обновлений one-step и 2000 BPTT на 6 шагов. Индексы minibatch совпадают.
Для BPTT берётся выбранная one-step модель и новый optimizer.
Нормировка входов рассчитывается только по train; масштабы приращений и loss
обеих ветвей совпадают точно. Отдельного слагаемого ошибки ускорения нет.

При BPTT начальная история реальная, затем в неё сдвигаются собственные
прогнозы без detach. Будущие ощущения — только метки loss.
Команды записанного отрезка известны как условие прогноза, подаются по одной.
Ошибка истории и очереди не включается в loss: копирование не обучается.

One-step checkpoint выбирается по validation RMSE скорости на 20 ms;
BPTT — по среднему RMSE скорости на 20/60/120 ms, как прежде.
Тестовые эпизоды не участвуют в выборе. Оценка траекторий использует прежние
231 окно H=20, stride=5. Нормированный loss — все окна H=6, stride=1:
2370 train и по 1185 validation/test. Эти два набора окон не смешиваются.

## Результат выполненного запуска — 2026-11-05

Все восемь ветвей завершены за 104,27 s суммарно, включая выбор моделей
и оценки на CPU ноутбука. Во всех четырёх механиках выбранные BPTT веса ветви
`current` побитово совпали с исходными checkpoints: контроль воспроизведён.
Выбранные BPTT updates без/с историей: 1800/400, 2000/1600,
2000/1600, 2000/2000. Остановка по прежнему бюджету обновлений, не по доказанной
сходимости. Это один seed, статистическая устойчивость не установлена.

RMSE скорости на test, **mm/s**, на прежних 231 окне:

| Механика | 20 ms, без / с историей | 120 ms, без / с историей | 400 ms, без / с историей |
| --- | ---: | ---: | ---: |
| 1. Без упругости и задержек | 0,432 / 0,795 | 0,893 / 1,227 | 0,965 / 1,324 |
| 2. Упругость | 0,556 / 2,306 | 0,893 / 1,896 | 0,933 / 1,610 |
| 3. Также транспортная задержка | 0,447 / 0,721 | 0,819 / 1,796 | 0,885 / 1,310 |
| 4. Также динамика активации | **0,506 / 0,263** | 1,107 / 1,302 | 1,005 / 1,969 |

В варианте 4 история уменьшила одношаговую ошибку скорости на 48%, но
увеличила её через 120 ms на 18%, через 400 ms на 96%. На validation история
помогла: RMSE скорости на 20/60/120 ms уменьшилась с 1,840/4,328/5,584
до 0,557/1,741/2,967 mm/s. Поэтому test не подтверждает единообразного
переноса улучшений с validation на другие эпизоды.

Нормированный шестишаговый loss по всем окнам, **без / с историей**:

| Механика | Train | Validation | Test |
| --- | ---: | ---: | ---: |
| 1 | 0,001421 / 0,013953 | 0,309415 / 0,396461 | 0,019265 / 0,035442 |
| 2 | 0,014465 / 0,052410 | 1,061662 / 1,148330 | 0,026558 / 0,078099 |
| 3 | 0,016117 / 0,049090 | 0,937185 / 1,182366 | 0,024247 / 0,075130 |
| 4 | **0,017745 / 0,014270** | **0,480095 / 0,111417** | **0,040623 / 0,032666** |

Это MSE физических состояний, поделённых на train STD одношаговых изменений;
среднее по всем каналам и шести горизонтам. Поэтому улучшение этого числа
совместимо с ухудшением скорости на отдельном позднем горизонте.
В частности, test loss варианта 4 уменьшилась на 20%.

Поканальный нормированный RMSE варианта 4, объединённый по всем шести шагам test:

| Канал | Без истории | С историей |
| --- | ---: | ---: |
| Положение | 0,07869 | 0,07187 |
| Скорость | 0,33104 | 0,30494 |
| Верхнее волокно | 0,07049 | 0,06985 |
| Нижнее волокно | 0,07420 | 0,07110 |
| Верхняя активация | 0,26817 | 0,19980 |

Наблюдение ограниченное: история дала пользу части прогнозов полной механики,
но не стала общим улучшением, а в трёх более простых вариантах результат хуже.
Это не доказывает бесполезность памяти при ограниченных сенсорах: здесь прямой
доступ к активации и длинам сохранён. Возможные причины ухудшения — избыточные
коррелированные входы, более сложная оптимизация при прежнем бюджете и накопление
ошибок собственных кадров при развёртке. Их причинный вклад этим сравнением
не разделён; отдельная абляция скрытой активации не проводилась.

Количество параметров без/с историей: 17410/19970, 17924/23044,
17924/23044, 18438/26118. Точность производных по командам и обучение actor
через новую модель не проверялись. Демонстрация по-прежнему использует эвристику.

## Воспроизведение

Актуальный короткий вариант — три прошлых кадра, 60 ms при шаге 20 ms:

```bash
.venv/bin/python3 -m myo.train_vertical_history \
  --history-steps 3 \
  --output-dir runs/vertical_sensory_history_60ms \
  > runs/vertical_sensory_history_60ms.log 2>&1
```

Команда прежнего опыта на 200 ms:

```bash
.venv/bin/python3 -m myo.train_vertical_history \
  --reference runs/vertical_predictor \
  --output-dir runs/vertical_sensory_history \
  > runs/vertical_sensory_history.log 2>&1
```

Выходной каталог должен быть новым. Данные/веса остаются в игнорируемом `runs/`.
Контракт `myo.vertical_sensory_history.v1` фиксирует длину и порядок истории,
шаг, физическую конфигурацию, исходники, архитектуру, нормировку и SHA весов.
Старые checkpoints не меняются; старый загрузчик отвергает новый формат.
Ветвь без истории дополнительно сравнивается побитово с прежними BPTT весами.

## Сокращение истории до 60 ms — 2026-11-05

Завершены все восемь ветвей с прежними seed, данными, нормировкой, loss,
расписанием и выбором checkpoint; суммарно 89,23 s. История теперь содержит
три прошлых кадра: 20/40/60 ms назад. Входы MLP для механик 1/2/3/4:
10/18/18/26 чисел. Для полной механики архитектура `26 → 128 → 128 → 6`,
20742 обучаемых параметра. Код и default прежнего воспроизводимого опыта
не менялись; длина новой памяти явно задана CLI и сохранена в metadata.

При каждом BPTT переходе история сдвигается вместе с физическим прогнозом:

```text
текущее s0,  история [s−1, s−2, s−3]
текущее ŝ1,  история [s0,  s−1, s−2]
текущее ŝ2,  история [ŝ1,  s0,  s−1]
текущее ŝ3,  история [ŝ2,  ŝ1,  s0]
текущее ŝ4,  история [ŝ3,  ŝ2,  ŝ1]
```

Только начальные ощущения реальные; новые кадры берутся из своих прогнозов.
Граф при сдвиге не обрывается: ошибка позднего шага проходит также через
ранние прогнозы, попавшие в историю. Копирование истории не имеет отдельного loss.

Полная механика, выбранные BPTT checkpoints, test скорость **mm/s**:

| Окно | 20 ms | 60 ms | 120 ms | 400 ms | Нормированная test MSE, H=6 |
| --- | ---: | ---: | ---: | ---: | ---: |
| Без истории | 0,506 | 0,906 | 1,107 | **1,005** | 0,040623 |
| 200 ms | **0,263** | 0,737 | 1,302 | 1,969 | 0,032666 |
| **60 ms** | 0,333 | **0,703** | **0,876** | 1,334 | **0,021743** |

Короткое окно уменьшило test MSE на 33% относительно 200 ms и на 46%
относительно отсутствия истории. На 120 ms RMSE скорости снизилась на 33%
относительно 200 ms. На 20 ms длинная история точнее, на 400 ms исходная
модель без истории по-прежнему лучше. Общего превосходства по всем горизонтам нет.

Нормированная MSE короткого окна по всем окнам H=6:

| Механика | Train | Validation | Test | Test, 200 ms |
| --- | ---: | ---: | ---: | ---: |
| 1 | 0,003001 | 0,345608 | 0,024468 | 0,035442 |
| 2 | 0,029556 | 0,966207 | 0,047969 | 0,078099 |
| 3 | 0,020253 | 0,776777 | 0,031567 | 0,075130 |
| 4 | 0,009970 | 0,095317 | 0,021743 | 0,032666 |

Выбранные BPTT updates с короткой историей: 1800/2000/2000/2000.
В механиках 1–3 итоговая test MSE лучше длинного окна, но хуже отсутствия
истории. Все контрольные BPTT веса снова побитово совпали с исходным опытом;
SHA256 эпизодов совпали с опытом 200 ms. Это сравнение одного seed и прежнего
бюджета, не установленный предел точности и не проверка моторного actor.
Данные результатов: `runs/vertical_sensory_history_60ms/summary.json`.
