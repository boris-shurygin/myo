# Рекуррентный резервуар вместо явного окна ощущений

Идея взята из [Neural reservoir control of a bio-hybrid soft arm](https://doi.org/10.1073/pnas.2522094123)
и проверена по [исходному коду авторов](https://github.com/GazzolaLab/SoftArmRC/blob/main/core/core_functions.py).
Там используются фиксированные входные и рекуррентные матрицы, обновление
через `tanh`, спектральный радиус 0,8 и плотность связей 10%.
На reset выполняются 20 повторов начального входа. В опубликованной
[конфигурации ANN](https://github.com/GazzolaLab/SoftArmRC/blob/main/rc_ann/input_parameters.json)
4096 нейронов; для локального первого сравнения выбраны 256.

Это адаптация способа памяти к нашему [вертикальному предиктору](vertical-predictor.md).
У авторов обучается управление мягкой рукой с PPO; здесь — только supervised
предсказание движения груза по прежним эвристическим эпизодам. Спайковые сети,
нейроморфное оборудование и моторная policy в этом опыте не используются.
Код написан локально; исходники, зависимости и веса авторов не импортируются.

## Представление памяти

Для текущего физического вектора ощущений `s_t`:

```text
z_t = (s_t - train_mean) / train_std
r_t = tanh(W_res @ r_(t-1) + W_in @ z_t)
```

`r_t` — 256 чисел, включающих текущий и прошлые кадры. Матрицы фиксируются
после случайной инициализации с seed 0; это buffers, а не параметры optimizer.
Ненулевые веса до масштабирования выбираются из N(0; 0,5²), маски связей
Бернулли с вероятностью 0,1; `W_res` масштабируется по собственным значениям
до спектрального радиуса 0,8. Значения памяти остаются в диапазоне `tanh`.
В отличие от явной истории, фиксированного отсечения на 200 ms нет.
Спектральный радиус сам по себе не доказывает устойчивость всей модели
с обучаемым прогнозом и обратной подачей собственных состояний.

На reset память нулевая, затем 20 раз получает начальный нормированный
физический кадр. Каждый эпизод проигрывается независимо для подготовки начальных
памятей окон; ни будущие состояния, ни другие эпизоды в `r_t` не входят.
Вход резервуара — только физические ощущения: положение/скорость и, по механике,
длины волокон/активации. Возбуждения не смешиваются с ощущениями.

Прогноз читается из текущих нормированных физических входов, дошедшей команды
и `r_t`. Два обучаемых варианта readout:

- `mlp`: прежние `128 Tanh → 128 Tanh → physical_size`;
- `linear`: один линейный слой на те же физические приращения.

Для полной механики: **264 входа → 128 → 128 → 6**, 51206 обучаемых параметров;
линейный вариант — **264 → 6**, 1590 параметров. Фиксированные матрицы содержат
ещё 67072 значения, большинство нулевые. Для сравнения: исходная MLP — 18438,
MLP с явными 200 ms истории — 26118 обучаемых параметров. Число параметров
не выравнивается; результат MLP нельзя приписывать только рекуррентной памяти.
Текущие физические входы нормированы прежними train статистиками, резервуарные
координаты читаются напрямую, без множителя 0,01 из actor-кода авторов.

## Обучение и причинность

Используются те же сохранённые данные четырёх механик: на каждую 6/3/3 эпизода
train/validation/test, по 8 s. SHA256 проверяется против опыта
[явной истории](vertical-sensory-history.md). Физика не пересобирается.
Предыдущие baseline checkpoints строго загружаются перед сравнением.

Расписание прежнее: seed 0, batch 128, Adam 0,001, clip 10,
1000 one-step + 2000 шестишаговых BPTT обновлений на ветвь.
Общие веса MLP инициализируются как baseline; столбцы для резервуара сначала
нулевые. Линейный readout целиком начинается с нуля. В обоих случаях начальный
прогноз — прежнее среднее приращение. Индексы minibatch совпадают с прежними
опытами. Бюджет по числу обновлений общий, по CPU времени не равный.

`s_next = s_current + delta_mean + delta_std * readout(...)`.
В rollout новая память рассчитывается по **собственному `s_next`**. Ни будущие
истинные физические состояния, ни предварительно вычисленная истинная память
после начальной точки в прогноз не подставляются. Транспортная очередь
40 ms остаётся явной, сдвигается точно и не включается в резервуар.

Loss прежняя: средняя квадратичная ошибка физических состояний, нормированная
STD одношаговых изменений train; отдельной ошибки ускорения/памяти/очереди нет.
Readout обучается BPTT через собственные физические прогнозы и фиксированное
обновление памяти, без detach. Фиксированная матрица допускает производную
по её входам; её собственные веса при этом не обучаются.

One-step checkpoint выбирается по validation RMSE скорости на 20 ms,
BPTT — по среднему на 20/60/120 ms. Test не выбирает веса.
Оценка траекторий: прежние 231 окно H=20, stride=5; нормированный loss:
H=6, stride=1, 2370 train и по 1185 validation/test окон.
Состояния активации и волокна остаются непосредственно доступными:
восстановление скрытой активации здесь не проверяется.

## Воспроизведение

```bash
.venv/bin/python3 -m myo.train_vertical_reservoir \
  --reference runs/vertical_predictor \
  --history-reference runs/vertical_sensory_history \
  --output-dir runs/vertical_reservoir \
  > runs/vertical_reservoir.log 2>&1
```

Новый каталог обязателен; данные и веса остаются в игнорируемом `runs/`.
`myo.vertical_reservoir.v1` фиксирует шаг, порядок ощущений/памяти, конфигурацию
резервуара, reset, архитектуру readout, исходники, нормировку и SHA весов.
Матрицы резервуара хранятся в checkpoint; несовместимые старые загрузчики
и другая конфигурация памяти отвергаются.

## Результаты выполненного запуска — 2026-11-05

Восемь ветвей завершены, `summary.json: status=complete`; суммарное время
190,59 s на CPU ноутбука, включая подготовку памяти и оценку. Это время
соседствовало с запуском тестов, не изолированный бенчмарк производительности.
Остановка по прежнему числу обновлений. Один seed резервуара/readout;
поиск удачной инициализации и подбор гиперпараметров не проводились.

Полная механика (4), test RMSE скорости, **mm/s**:

| Модель | 20 ms | 60 ms | 120 ms | 400 ms |
| --- | ---: | ---: | ---: | ---: |
| Текущие ощущения, MLP | 0,506 | 0,906 | **1,107** | **1,005** |
| Явные 200 ms истории, MLP | **0,263** | **0,737** | 1,302 | 1,969 |
| Резервуар 256, MLP | 0,539 | 1,456 | 2,024 | 1,820 |
| Резервуар 256, linear | 0,990 | 3,165 | 5,782 | 10,464 |

Все числа — выбранные по validation шестишаговые BPTT checkpoints на тех же
231 test-окне. Резервуар с MLP на 400 ms немного лучше явной истории,
но хуже исходного предиктора. На остальных показанных горизонтах вариант 4
с резервуаром хуже обеих прежних MLP.

Нормированная шестишаговая **test MSE**, все 1185 окон:

| Механика | Текущие ощущения | Явная история | Резервуар + MLP | Резервуар + linear |
| --- | ---: | ---: | ---: | ---: |
| 1 | 0,019265 | 0,035442 | 0,055948 | 1,327715 |
| 2 | 0,026558 | 0,078099 | 0,260856 | 0,670166 |
| 3 | 0,024247 | 0,075130 | 0,290932 | 0,891752 |
| 4 | 0,040623 | **0,032666** | 0,072564 | 0,451688 |

Для механики 4 нормированная MSE по частям данных:

| Модель | Train | Validation | Test |
| --- | ---: | ---: | ---: |
| Текущие ощущения | 0,017745 | 0,480095 | 0,040623 |
| Явная история | 0,014270 | 0,111417 | 0,032666 |
| Резервуар + MLP | 0,035546 | 0,366078 | 0,072564 |
| Резервуар + linear | 0,554005 | 0,786986 | 0,451688 |

Вариант reservoir + MLP также имеет более высокую train loss на выбранных
checkpoints всех механик: ухудшение нельзя объяснить только test-обобщением.
При этом выбор checkpoint зависит от validation скорости, а не train loss.
Выбранные BPTT updates MLP: 200/200/600/1600; linear: 2000 во всех механиках.
Ранний выбор MLP в первых механиках и продолжающееся улучшение linear к концу
не устанавливают, что дальнейшее обучение бесполезно.
В механике 4 validation-score linear за последние 600 обновлений уменьшился
с 4,758 до 4,616 mm/s. Это слабая динамика в конце заданного бюджета, не плато.

Возможные направления разбора, причинно не разделённые этим опытом:

- Масштаб и корреляция 256 новых входов меняют оптимизацию readout при прежнем
  learning rate. В частности, множитель 0,01 из actor-кода авторов не применён;
  его влияние требует отдельного сравнения с фиксированными остальными условиями.
- 256 нейронов дают другой набор временных признаков, чем 4096 у авторов;
  при данных входах и шаге полезная длительность памяти не измерялась отдельно.
- Собственные ошибки прогнозов влияют на будущую память; накопление ошибки
  может отличаться от конечного явного окна. Точные текущие активации/длины
  уже сообщают значительную часть состояния.

Проверка идеи завершилась отрицательным результатом для этой конфигурации
предиктора и бюджета. Она не воспроизводит целиком задачу/размер/обучение авторов
и не опровергает reservoir control. Использование модели для обучения actor,
качество производных относительно native-физики и поведение контроллера
в демо здесь не проверялись.

`scripts/audit_vertical_reservoir.py` независимо загрузил все 16 checkpoints,
восстановил начальные случайные матрицы и подтвердил их побитовое совпадение
с сохранёнными, проверил train-only нормировку и воспроизвёл все нормированные
ошибки. Результаты: `runs/vertical_reservoir/summary.json`, `artifact_check.json`.

```bash
.venv/bin/python3 scripts/audit_vertical_reservoir.py --run runs/vertical_reservoir
```
