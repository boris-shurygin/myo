# Интерактивная рука на скамье Скотта

Сборка для Linux-ноутбука, **2026-11-09**. MuJoCo-визуализация и обученная
PPO-policy управляют той же шестимышечной MyoArm с грузом1 kg.
Unreal/Chaos Flesh и деформируемая кожа относятся к дальнейшему визуальному этапу.

## Запуск

Из репозитория на графическом рабочем столе:

```bash
bash scripts/demo_arm.sh
```

Launcher сам выбирает `.venv/bin/python3`, переходит в корень проекта и
загружает **`runs/arm_continuation/best.zip`** с проверкой physics/observations
и метаданных. Его можно вызвать абсолютным путём из другого каталога.
Исходные веса нужны локально; launcher не скачивает и не обучает модель.

Полный эквивалент:

```bash
.venv/bin/python3 scripts/demo_arm_preacher.py \
  --controller runs/arm_continuation/best.zip --view
```

Окно работает до закрытия. На старте цель75°, рука начинает с20°.
После достижения цели контроллер продолжает удержание. Новая цель остаётся
заданной до следующего нажатия; четырёхсекундный учебный time limit не сбрасывает
ни позу, ни утомление, ни историю, ни очередь мышечных команд.
Явный reset происходит только поR; физический failure ставит демо на паузу.

## Управление

| Клавиша | Действие |
| --- | --- |
| ↑ / ↓ | Увеличить/уменьшить целевой угол на5° |
| Пробел | Пауза/продолжение |
| R | Начать заново:20→75°, свежая capacity, груз1 kg |
| 1 | Раздельная раскраска брюшек по активации, сухожилий по силе |
| 2 /3 /4 | Раскраска по активации /силе /растяжению |
| M | Следующая мышца в числовой панели |
| C | Показать/скрыть инженерные контактные оболочки |
| F | Восстановить вид камеры |
| Мышь | Вращение/масштабирование камеры |
| Esc | Закрыть окно |

Для клавиш окно должно иметь фокус. Триггер фиксирован на**100%**, как в
позиционном PPO-обучении. Клавиши `+`, `-`, `0` его не меняют; это явно показано
в подсказке. Возбуждения по-прежнему выбирает policy отдельно для каждой мышцы:
фиксированный trigger не означает постоянную максимальную активацию.

Видны текущий/запрошенный/сглаженный углы, масса, команды, задержанные команды,
активация, сила и растяжение сухожилия, длины тканей и capacity proxy.
Брюшки и сухожилия нарисованы отдельно; форма меняется по их длинам, цвет —
по выбранному сигналу. Контактные оболочки — инженерное приближение,
их размеры не являются анатомически откалиброванной кожей.

## Какая модель и какие ограничения

Используется прежняя лучшая по test policy **без предиктора**, lifetime212992:
validation9/9, test10/11, средняя tail RMSE1,940°; все пять test-перемещений
проходят. Удержание15° имеет ошибку5,668°. Цели обучения15–135°; выход за
исследованный диапазон не подтверждён, дополнительного верхнего физического
упора или clamp угла для демо не добавлено.

Транспорт40 ms, activation15/50 ms, независимая series elasticity и утомление
сохранены. Изображение работает на отдельной копии MuJoCo model/data:
камера и GUI-редактирование не изменяют физическое состояние руки.
Release/защитное торможение и управление при других массах не входили
в обучение этой policy. Это позиционное демо, не завершённая приёмка D1.

Сравнение новых предикторов не улучшило исходную демо-policy:
[результаты PPO](arm-anticipation-ppo.md). Для просмотра именно обученного
new60-last можно явно сменить checkpoint:

```bash
bash scripts/demo_arm.sh --controller runs/arm_anticipation_ppo/new60/last.zip
```

Автоматическая последовательность целей75→20→105→45° доступна с `--scripted`;
она явно перезаписывает ручную цель каждые4 s. По умолчанию этот режим выключен.
Headless-проверка той же policy:

```bash
.venv/bin/python3 scripts/demo_arm_preacher.py --seconds 16 --scripted
```

## Проверка изображения и завершения

GUI smoke открывает настоящее окно и завершает его через3 s:

```bash
bash scripts/demo_arm.sh --seconds 3
```

При проверке обнаружено зависание после публичного `launch_passive().close()`:
handle запрашивает завершение, но не ожидает native cleanup. Viewer руки
переведён на уже применённый в вертикальном стенде адаптер MuJoCo3.17
с собственным render-thread и `join()` перед освобождением ресурсов.
Повторный GUI smoke завершился с exit0 без зависания.
Regression проверяет ожидание cleanup и отдельную display-копию для обоих стендов.

Клавиатурный regression дополнен режимом fixed-trigger: изменение цели
сохраняет физическую позу/состояние мышц, release блокируется только в UI
этого режима. Для остальных запусков generic viewer прежние trigger-клавиши
сохраняются. Фактические проверки и снимки — [validation.md](validation.md).
