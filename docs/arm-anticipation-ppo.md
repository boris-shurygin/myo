# PPO с новым60-ms предиктором, старым и без предиктора

Протокол **2026-11-09**, после [продолжения предиктора](arm-anticipation60-continuation.md).
Проверяем пользу **фиксированного представления**, а не передачу готового
прогноза угла/скорости в actor или дифференцирование управления через предиктор.

## Схема и общий старт

Для каждой головы независимо:

```text
наблюдение153 → private128 →128 (обучается PPO) ───┐
                                                concat256 →128 →128 → actor / critic
наблюдение → encoder4×128 (заморожен) → ×0,25 ────┘
```

Actor выдаёт параметры шести Beta-распределений прямых возбуждений;
critic оценивает дисконтированный return. Их private и post-concat слои
раздельны, frozen encoder общий. У none вместо признаков128 нулей.
Prediction head/normalization сохраняются в policy для проверки identity,
в PPO-forward не используются и не обучаются.

| Ветка | Encoder | Прогноз, на котором он обучался |
| --- | --- | --- |
| none | Не используется | Нет |
| old20 | 27→4×128 SiLU | Изменение20 физических каналов за20 ms |
| new60 | 33→4×128 SiLU | Изменение тех же каналов за60 ms, head дополнительно получает новую команду |

Old20 — `runs/arm_preacher_balanced/body/best.pt`.
New60 — `runs/arm_anticipation60_extended/best.pt`, update448000.
У old20 один слот очереди команд, у new60 два; это сравнение двух готовых
представлений, **не изолированная абляция только горизонта**.
Новая команда не входит в encoder33 и не создаёт циклическую зависимость actor.
Исходные153 ощущения/история/очередь доступны private-ветвям во всех вариантах.

Общий родитель — **`runs/arm_continuation/best.zip`**,212992 перехода,
без предиктора. Из него копируются все обучаемые веса и RMSprop moments.
Входные128 колонок первого post-concat слоя, читающие предиктор, обнуляются
**во всех трёх ветках**, включая none; их moments также нулевые.
Родитель всегда получал здесь нули, поэтому начальные Beta-параметры и
value-функция сохраняются побитово (проверены27 train-пар).
Новая ветвь сначала не меняет команд, но её readout получает градиент с первого
PPO-update и может научиться извлекать признаки.
Это общий warm-start, не обучение с нуля и не продолжение прежних разных
frozen-родителей. Начальные private/tail weights, optimizer и умения одинаковы.

## Зафиксированные условия

- **65536 новых переходов** каждой ветке; lifetime278528 на завершении.
- Seed0, перезапуск среды/RNG один раз на старте; непрерывное обучение внутри ветки.
- RMSprop **LR3e−5**, rollout1024, batch128, epochs10, gamma0,99, GAE0,95,
  clip0,2, entropy0,001, value0,5, grad-norm0,5, target-KL0,03.
- Прежние27 train-пар,9 validation и11 исторических test; reward неизменна.
- Груз1 kg, trigger1, transport40 ms, activation15/50 ms, series elasticity,
  control20 ms, physics1 ms. Физика, входы private и reward не меняются.
- Validation каждые8192; best по failures/pass/mean tail RMSE, исходный
  checkpoint также кандидат. Сохраняются initial/best/last и промежуточные модели.
- Все три выбора совместно фиксируются до test; budget не меняется по test.
  Остановка по одинаковому бюджету, не свидетельство плато.
- Дополнительно: реальные SGD/KL-stop, best/last, ошибки по заданиям,
  вмешательства в признаки и непрерывные смены цели.

Gain0,25 одинаков, но RMS самих представлений может различаться: его измеряем
в диагностике. Один seed и знакомый test не устанавливают статистическую
устойчивость. Здесь проверяется подключение признаков к уже умеющей policy;
обучение с нуля может дать другой результат. Release/защита/UE не входят в опыт.

## Воспроизведение

```bash
taskset -c 0 env OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 MKL_NUM_THREADS=1 \
  .venv/bin/python3 scripts/compare_arm_anticipation_ppo.py train --kind none
taskset -c 2 env OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 MKL_NUM_THREADS=1 \
  .venv/bin/python3 scripts/compare_arm_anticipation_ppo.py train --kind old20
taskset -c 4 env OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 MKL_NUM_THREADS=1 \
  .venv/bin/python3 scripts/compare_arm_anticipation_ppo.py train --kind new60
.venv/bin/python3 scripts/compare_arm_anticipation_ppo.py evaluate
```

Артефакты — ignored `runs/arm_anticipation_ppo/`; каталоги не перезаписываются.
Strict loader сохраняет native contract, predictor identity, индексы/порядок,
gain, source hash и digest frozen encoder/head/нормировки; загрузка не требует
исходного `.pt`, всё необходимое включено в checkpoint policy.
Демо поддерживает новый тип через `scripts/demo_arm_preacher.py`.

Начальные regression-проверки: **3 passed in3,38 s**. Проверены точное сохранение
поведения и moments, обновления private при неизменном predictor, строгий
roundtrip и отказ при подмене frozen-весов.
Полный suite и повтор UDP-проверки — [validation.md](validation.md).

## Завершённое обучение

Все три ветки завершили по**65536** новых переходов, суммарно196608.
Остановка `fixed_equal_budget`; плато этим не установлено.
Все frozen-веса/нормировки/gain остались побитово неизменными.

| Ветка | Best lifetime | Best val, ° | Pass | Последняя val, ° | Pass | SGD | KL-stop /64 |
| --- | ---: | ---: | --- | ---: | --- | ---: | --- |
| none | 278528 | 1,148 | 9/9 | 1,148 | 9/9 | 5000 | 2/64 |
| old20 | 253952 | 1,196 | 9/9 | 1,202 | 8/9 | 4996 | 2/64 |
| new60 | 212992, initial | 1,315 | 9/9 | 1,632 | 8/9 | 5043 | 2/64 |

Trainable parameters одинаковы: **172941**. Frozen parameters none/old20 —55700
(неиспользуемый encoder/head включён и в none для одинаковой формы сети),
new60 —73748. Wall-clock с validation:792,98/809,80/811,83 s;
это не отдельный benchmark производительности inference.
У none вся validation-траектория и число SGD воспроизвели прежний
`runs/arm_predictor_lr/none_3e5`: замена неиспользуемых колонок нулями не
изменила обучение. Начальные обучаемые веса и все RMSprop accumulators
у трёх веток дополнительно сравнены по именам параметров.

У new60 выбран **initial**, где readout предиктора ещё нулевой.
Поэтому test такого best описывает сохранённого родителя и **не доказывает
полезность нового предиктора**. Результат настоящего PPO-продолжения new60
нужно смотреть по last и истории. Выбор не подменяется более удачным test.

## Test после фиксации всех выборов

Указана средняя tail RMSE по11 заданиям, не RMSE всей переходной траектории.
Pass требует90% отсчётов последней секунды с ошибкой≤3° и скоростью≤5°/s,
без failure за4 s. Общий исходный родитель: **1,940°;10/11**.

| Ветка | Выбранный best test, ° | Pass | Last test, ° | Pass |
| --- | ---: | --- | ---: | --- |
| none | 2,264 | 8/11 | 2,264 | 8/11 |
| old20 | 2,125 | 9/11 | 2,144 | 8/11 |
| new60 | 1,940, initial | 10/11 | **2,709** | **7/11** |

Физических failures нет ни у одного best/last. New60-last не достигает
test-удержаний120/130/15° и подъёма60→125°. Проходят4 из5 перемещений,
у none/old20-best —5 из5. New60-best повторяет исходного родителя, включая
его неточное удержание15°; это не результат использования60-ms признаков.

В выбранных best old20 немного лучше нового none-продолжения по test,
но оба уступают исходному родителю. В конце одинакового бюджета old20/none
имеют8/11, new60 —7/11. Новый predictor с более точным общим прогнозом сам
по себе не сделал PPO лучше; на этом общем старте его подключение ухудшило
сохранение навыков. Это один seed и ограниченный warm-start бюджет,
а не доказательство бесполезности любых60-ms представлений.

New60 не испытывал большей нехватки SGD:5043 против5000/4996,
у всех только2 KL-stopped rollout из64. Поэтому объяснение «новому
предиктору просто не дали достаточно minibatch updates из-за KL»
этот опыт не поддерживает. Полноценное плато не установлено.

## Использование признаков и непрерывное управление

После выбора моделей выполнены read-only вмешательства на5400 состояниях
из **train-эпизодов** прежнего body-dataset. Средний вектор h вычислен только
по ним; private получает прежнее наблюдение. Mean/zero дополнительно проверены
в замкнутом контуре на9 validation-заданиях. Это локальная абляция обученных
моделей, не переобучение и не критерий выбора.

| Модель | Среднее Δu при h→mean | Native val, °;pass | Mean val | Zero val |
| --- | ---: | --- | --- | --- |
| old20-best | 0,00061 | 1,196;9/9 | 1,286;9/9 | 1,363;9/9 |
| old20-last | 0,00063 | 1,202;8/9 | 1,223;8/9 | 1,318;8/9 |
| new60-last | 0,00050 | 1,632;8/9 | 1,791;8/9 | 1,856;7/9 |

New60-best — initial с нулевым readout; вмешательства сохраняют его поведение
точно. У none также точная инвариантность: передаваемый h всегда нулевой.
Одинаковые rollouts для таких случаев повторно не считались.

На общем train-batch raw RMS h old20/new60 —1,3712/0,5497,
после gain0,25 —0,3428/0,1374. Новый latent примерно в2,5 раза меньше,
хотя gain одинаков. Норма actor-весов, читающих128 признаков, выросла с0
до0,51510 у old20-last и0,47356 у new60-last. Предикторы побитово прежние.
Команды при замене признаков меняются мало:0,00050 соответствует0,05
процентного пункта возбуждения в среднем по координатам и5400 состояниям.
В конкретных состояниях эффект может быть больше.

**Представления используются, но влияние невелико.** Для new60-last они
помогают внутри этой конкретной policy: отключение ухудшает замкнутое управление.
Это не компенсирует ухудшение относительно исходного родителя или контролей.
Хорошая ошибка прогноза не гарантирует удобные для PPO признаки; здесь
готовые признаки не добавляют недоступных private наблюдений, а предлагают
другое их кодирование. Факт меньшего RMS — гипотеза для следующей абляции,
не установленная причина неуспеха. Готовые60-ms прогнозы actor напрямую
не получал. Проверяется перенос encoder, а не model-based планирование.

Последняя rollout explained variance критика none/old20/new60:
0,9973/0,9944/0,9932. Это внутренний показатель на PPO-rollout targets,
не независимая проверка правильности value во всех состояниях.

Каждый выбранный best исполнил16 s,75→20→105→45° по4 s **без reset/failure**:

| Ветка | Tail RMSE четырёх участков, ° |
| --- | --- |
| none | 0,081 /1,137 /2,133 /1,483 |
| old20 | 0,145 /2,630 /2,247 /0,609 |
| new60 initial | 0,527 /1,496 /2,745 /0,101 |

Дополнительно настоящий `demo_arm_preacher.py` исполнил new60-last16 s
с800 кадрами `myo.character_state.v2`, одним episode/run_id, sequence0…799,
непрерывным временем и сохранёнными physics1 ms/control20 ms, без failure.
Full RMSE20,900° включает большие начальные ошибки после смены цели
и не сравнивается напрямую с tail RMSE выше.
