# Прямой PPO с нуля: задержка и управление по 10 мс

Начато 2026-11-11 по просьбе владельца. Меняем транспортную задержку руки
40→10 мс и период команд 20→10 мс. Новые суставы, предиктор, иерархия,
эталонные ускорения и обучение с учителем в этот опыт не входят.
20 мс для стоп — пожелание для будущей большой модели, здесь не реализуется.

## Сохранённые условия

Повторяем найденные настройки успешного
[позиционного PPO](arm-stagnation-exploration.md):

- MyoArm, один локоть, шесть мышц; исходные силы, контакты, масса самой руки,
  независимые series-elastic сухожилия и физический шаг 1 мс.
- Нарастание/спад активации: константы 15/50 мс, без изменения. Это не время
  достижения пика: экспоненциальная активация не достигает асимптоты точно.
- Actor и critic — раздельные эффективные 4×128 SiLU; независимые Beta-команды
  шести возбуждений, RMSprop, LR1e−5, batch128, 10 epochs, γ0,99, λGAE0,95,
  clip0,2, entropy0,001, vf0,5, targetKL0,03, grad norm0,5.
- Тот же причинный detector застоя, окно400 мс, рост200/спад100 мс,
  максимальная температура16. Его таймер пересчитан на реальный шаг10 мс.
- Reward без изменений на решение:0,1×позиционное слагаемое и physical failure,
  без скорости, экономии и бонуса за возбуждение. Скорость участвует в pass.
- 18 учебных условий: (120→120°,130→120°,135→135°) ×0,5/1/2 кг ×наклон120/150°.
  Эпизоды4 с, холодный native reset, trigger1, capacity1.
- Те же27 validation и8 известных test условий. Test используется только
  после обучения, не для выбора весов или остановки. Он уже был просмотрен в
  прежних опытах и не является новым независимым holdout.

Заново инициализируются все обучаемые веса, optimizer state и счётчики.
Старый metadata читается только как описание учебной программы; его weights
не загружаются. Предикторные технические ветви прежней policy не используются
и заморожены. Переноса навыка, teacher preload и имитационных обновлений нет.

## Следствия смены шага

Численные PPO-параметры намеренно не подбираются заново. Поэтому физический
горизонт γ/GAE и rollout256 решений сокращается вдвое; rollout теперь2,56 с
на среду. Это не изолированная абляция только моторной задержки.
Per-step reward0,1 сохранён, число решений/наград за секунду удвоено.
Два кадра истории теперь соответствуют10/20 мс вместо20/40 мс.

Новая очередь содержит один блок из шести команд вместо двух; данные сжимаются
без потери значений физических подшагов. Поэтому вход150 каналов вместо156.
Ширина и глубина скрытых слоёв прежние, меняется только размер входной матрицы.
Контракт `myo.arm_timing.v1` хранит timing/config, порядок и масштабы входов,
action mapping, reward, exploration, хеши динамики/геометрии/адаптера.
Прежние pinned модули и checkpoints не изменяются и новый контракт отвергают.

## Прогон и остановка

`src/myo/arm_timing.py` — адаптер существующих reward, policy и мышечной физики;
`scripts/train_arm_timing.py` — fresh PPO. Один тяжёлый запуск, CPU12–15,
nice19, ionice idle, Torch/BLAS по одному потоку,4 среды. Evaluation вынесен
в отдельный процесс и не расходует RNG и состояния учебных сред.

Максимум1048576 переходов; проверки каждые32768. Остановка по всем18/18 train
и27/27 validation pass без physical failure либо после минимум262144 переходов
при четырёх последовательных проверках без накопленного улучшения validation
RMSE≥2%/роста pass при сопоставимой ошибке. Cap отдельно от плато.
Pass: полный4-секундный эпизод; ≥90% последней секунды в пределах3° и5°/с.
Оценка — deterministic Beta means, без случайных рывков.

```bash
nice -n 19 ionice -c 3 taskset -c 12-15 env \
  OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 MKL_NUM_THREADS=1 \
  .venv/bin/python3 scripts/train_arm_timing.py \
  --out runs/arm_timing/fresh_10ms
```

Артефакты локальные ignored: `summary.json`, `progress.csv`, best/last с metadata,
оценки train/validation/test. Исходное демо40 мс остаётся отдельным.

205 passed,6 warnings за120,35 с. Обучение завершено после262144 переходов
по правилу validation-плато,не по cap1048576. Новый полезный controller не
получен. Повторная проверка сохранённых checkpoints завершена:

Выполнены256 rollouts и20480 RMSprop updates:все по80,ранних KL-остановок0.
Время до остановки2673,0 с,без последующей повторной оценки best/last.
Pressure>0,5 на84,90% учебных переходов. Средние sampled excitations за весь
прогон в порядке action mapping:0,131/0,268/0,412/0,193/0,175/0,339.
Команды>0,95 встречались у всех мышц,например у BRA8,13% переходов.
Сильные команды исследовались,но это не доказательство обнаружения полезных
достаточно длительных последовательностей или их закрепления.

Median explained variance critic по rollout-return targets0,982,
median последних32 rollouts0,9965;в24 из256 rollouts EV отрицателен,
последний−1,220. Эти targets содержат bootstrap/GAE,независимый MC-return
не измерялся. Поэтому хорошие отдельные EV не доказывают корректность critic
или advantages. Веса и распределения менялись,но награда/точность actor не росли.

Прежний успешный40/20-мс controller имел длительную предысторию обучения;
его финальные344064 stall-перехода начинались с уже обученного parent.
Наш запуск —fresh initialization с LR,выбранным для того продолжения.
Такое сравнение не устанавливает,что меньшая задержка ухудшает обучение.
Установлено только,что этот перенос набора настроек не дал обучения с нуля
за выполненный бюджет. Возможные причины —пригодность LR для старта,
исследование длительных усилий и баланс entropy/reward;они здесь не разделены.
