# Прямой предиктор ощущений через60 ms

Продолжение с теми же данными/LR и увеличенным бюджетом:
[448000 updates, ошибки и отклик на команды](arm-anticipation60-continuation.md).
Ниже сохранены протокол и результаты первого этапа150000.

Протокол от **2026-11-09**. Цель — отдельно обучить представление,
описывающее динамику к моменту, когда новая команда уже начала действовать.
Схема для дальнейшего PPO остаётся прежней: frozen-представление предиктора
плюс собственное обучаемое представление actor/critic. В этом опыте PPO не запускается.

## Входы, выходы и архитектура

Используем ту же MyoArm с1 kg, транспортом40 ms, активацией15/50 ms,
отдельной series elasticity, physics1 ms и control20 ms. Физику не меняем.

Encoder: **33→128→128→128→128**, SiLU. Вход — прежние20 физических каналов
(угол, скорость локтя, шесть относительных длин волокон, шесть активаций,
шесть remaining-capacity proxy), обе шестиканальные команды FIFO и масса.
Прежде encoder получал27 входов: только ближайшие шесть FIFO-команд.
Датчики сил/сухожильного растяжения в этот набор20 выходов не добавляются.

Представление128 не зависит от новой команды. Она присоединяется **после encoder**:
**concat(z128,u6)→128 SiLU→linear20**. Нелинейный слой головы позволяет
реакции на команду зависеть от состояния. Возбуждения нормируются2u−1.
Голова выдаёт нормированные приращения ощущений за60 ms; конечный прогноз —
текущее состояние плюс восстановленное приращение. Ограничивающего tanh на выходе нет.
Выходы — прежние20 каналов; это не расширенная анатомическая сенсорная модель.

Три такта: очередь[old0,old1] действует на0–20 и20–40 ms, текущая новая команда
на40–60 ms. Команды следующих тактов на исход до60 ms не влияют:
первая из них поступит на границе60 ms. Эта причинность проверяется реальным
симулятором, а не предполагается по структуре сети. Их нет во входах.

Прогноз прямой, **без BPTT**: labels берём из фактического состояния через три
перехода; обычный backprop идёт через один encoder/head. Сам MuJoCo не дифференцируем.

## Данные и обучение

Повторно используем `runs/arm_preacher_balanced/body/dataset.npz`:621 эпизод,
124200 переходов, разнообразные hold/ramp/jitter, плавные open-loop и policy-пробы.
Старые train/validation/test роли эпизодов сохраняются. Входы только из кадраt
и его действия; метка — `next_observations[t+2]`. Окна не пересекают reset,
и все три перехода должны быть valid. До обучения проверяется непрерывность
физических каналов и FIFO внутри эпизодов.

Новая сеть с seed0; encoder не переносим из одношаговой модели. Нормировки
приращений mean/STD вычисляются **только по train delta60**, STD floor1e−5,
после этого фиксированы. Loss — средняя normalized MSE20 каналов.
Sampling: прежняя смесь50% uniform и50% по непустым ячейкам
угла/скорости/расхождения ближайшей команды с активацией.

RMSprop LR1e−4, alpha0,99, eps1e−5, batch128, grad norm0,5.
До150000 updates, validation каждые1000. Best — минимальная balanced MSE
полного validation. После20000 updates остановка при отсутствии накопленного
улучшения0,5% за20000 updates. Иначе остановка по бюджету не означает плато.

До test фиксируется hash best; проверяется строгая загрузка и replay validation.
Checkpoint хранит horizon60, порядок входов/выходов, action mapping,
полный physical contract, dataset identity, нормировки и архитектуру.
Он несовместим со старым27-входовым predictor/PPO и отвергается при несовпадении
контракта. Интеграции в actor/critic в этом опыте нет.

## Проверка

На одних test-окнах сравниваем прямой прогноз, прежний одношаговый predictor
из `runs/arm_preacher_balanced/body/best.pt`, применённый трижды, и persistence.
Одношаговому baseline также не даём неизвестных будущих действий: за60 ms
используется только текущая новая команда и исходная FIFO.
Это сравнение двух систем с разными архитектурой/задачей/нормировками обучения,
не чистая абляция одного горизонта. Их normalized loss напрямую не сравниваем.

Метрики: ошибки каждого физического канала в его единицах; RMSE относительно
RMS естественного изменения за60 ms и20 ms. Отдельно hold/ramp/jitter/policy/open-loop.
Test исторический и уже использовался в прежних исследованиях; новый predictor
его примеры в обучение не получает.

Дополнительно после выбора проверяем разницу последствий двух команд из одного
и того же состояния настоящего симулятора. Это показывает качество action-response,
которое может быть скрыто небольшой общей ошибкой состояния.

```bash
taskset -c 2 env OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 MKL_NUM_THREADS=1 \
  .venv/bin/python3 -m myo.train_arm_anticipation
```

Все артефакты остаются ignored в `runs/arm_anticipation60/`.

Набор после построения окон:66726 train /27522 validation /28710 test,

Средний выигрыш над прежним составным прогнозом —около13,4% по углу и14,0%
по скорости. Он не равномерен по источникам.

### Остальные ощущения и масштаб ошибки

Для прямого предиктора угол0,1559° равен**7,2%** RMS естественного изменения
угла за60 ms и**21,3%** изменения за20 ms. Скорость3,441°/s —**16,4%** и**39,4%**
соответственно. Это отношения RMS по всей выборке, не относительная ошибка
каждого отдельного кадра; покадровое деление на малое изменение не применяется.

| Каналы прямого прогноза | RMSE в физических единицах | RMSE / изменение60 | RMSE / изменение20 |
| --- | --- | --- | --- |
| Длины шести волокон | 0,000567–0,002206 от оптимальной длины | 8,4–17,3% | 23,9–49,2% |
| Активации шести мышц | 0,00855–0,00956 от диапазона0…1 | 16,9–22,0% | 26,2–33,2% |
| Capacity proxy | примерно0,000006–0,000009 от диапазона0…1 | 7,3–9,6% | 21,8–28,8% |

По активациям прямой прогноз **хуже** прежнего ×3: его RMSE по мышцам
0,00132–0,00417 против новых0,00855–0,00956. Последние числа соответствуют
примерно0,86–0,96 процентного пункта активации. Небольшой выигрыш угла/скорости
не означает улучшения всех20 выходов. Полная поканальная таблица с единицами
и масштабами находится в локальном `report.md` и `test.json`.

### Разница последствий команд

После выбора best воспроизведены **16 состояний** из8 test-эпизодов hold/ramp:
начальные углы30/60/90/120°, capacity1, времена100 ms и1 s.
Из каждого состояния выполнены две ветви с командами
`clip(u ± [0.15,0.15,0.15,-0.15,-0.15,-0.15],0,1)`.
Состояние восстанавливается воспроизведением записанного префикса;33 входа
совпали с исходной записью побитово. Мышцы/скорость/очередь не подменялись.

| Прогноз разницы двух исходов | Прямой60 | Прежний ×3 | RMS реального эффекта |
| --- | ---: | ---: | ---: |
| Ошибка изменения угла, ° | 0,1137 | 0,2051 | 0,1852 |
| Ошибка изменения скорости, °/s | 9,072 | 3,367 | 26,028 |

По положению прямой прогноз лучше: ошибка61,4% эффекта против110,8%.
По скорости хуже:34,9% против12,9%. Обе модели угадали знак изменения скорости
во всех16 пробах с эффектом>0,1°/s. Это ограниченный тест одной пары направлений
возбуждения, не проверка всего Jacobian и не гарантия правильных градиентов.
Небольшая обычная ошибка состояния скрывает более заметную ошибку реакции на действие.

### Что установлено

Прямой60-ms предиктор с поздним вводом команды обучается обычным backprop
без BPTT и немного точнее в среднем прогнозирует угол/скорость на старом test.
При этом часть сенсорных выходов, скорость реакции на смену команды и прогноз
актуальных policy хуже прежней модели. **Большая полезность его представления
для контроллера пока не установлена.**

Результат не опровергает идею упреждения: обучение продолжало улучшаться,
архитектура/входы/нормировки отличаются от старого предиктора, и PPO с новым
encoder ещё не проверялся. Нужны отдельные проверки дальнейшего обучения,
покрытия текущих policy-состояний и реакции на команды; их результаты нельзя
заранее приписать одному горизонту. Новые test- и counterfactual-метки не были
перенесены в train после оценки.

В будущем actor/critic получают замороженный encoder33→128 и собственные
обучаемые ветви. Новую голову прогноза не следует подменять старым linear20;
она нужна для отдельной оценки действия. Старые PPO checkpoints/default demo
не изменены.

Строгая загрузка и идентичность replay validation прошли; нормировки сохранены,
физическая причинность подтверждена тестом. Результаты проверок:
[validation.md](validation.md#прямой-предиктор-ощущений60-ms--2026-11-09).
Артефакты ignored: `training.json`, `test.json`, `command_contrasts.json`,
`policy_probes.json`, `comparison.png`/`.svg`, `report.md`, weights и metadata.
