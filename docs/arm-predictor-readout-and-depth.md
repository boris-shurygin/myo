## Почему prediction head умеет читать h, а PPO пока использует его плохо

Предиктор:27 входов →4×128 SiLU →h128 →linear20. Кодировщик и linear20
обучались **совместно** по нормированной ошибке фактического следующего состояния.
На каждом примере есть отдельная ошибка двадцати физических каналов. Head
адаптировался к координатам, масштабу и корреляциям именно этого h; универсального
масштаба скрытого представления мы не задавали. Нормировка физических labels
не является нормировкой скрытых128 признаков.

Actor получает frozen-h и собственную обучаемую private-ветку. Первый слой после
объединения вычисляет `z = W_h h + W_p p + b`, затем SiLU и следующие слои.
PPO заново учит это преобразование по advantage; физическая prediction head
не участвует в выборе команды, её веса не передают контроллеру готовое
обратное отображение «цель → возбуждения». Обучаемый private-вход включает цель,
которой нет во входе предиктора. Для critic также нужны признаки цели и будущей
награды, а не только следующего физического состояния.

В исходной инициализации на общем5400-state diagnostic batch RMS вкладов
`W_h h`/`W_p p` составляли2,401/0,486. При gain0,25 —0,600/0,486.
Это измеренный перекос вкладов, не доказательство подавления цели или
насыщения всех нейронов. SiLU не следует описывать как Tanh; само большое
число не означает исчезновения градиента. Новые ветви, нелинейности,
разные градиенты и KL-остановки делают условия оптимизации другими.

Разделили постоянное среднее по состояниям и centered-изменения каждого вклада
на том же batch. Здесь `RMS² = mean_RMS² + centered_RMS²`:

| Вклад в первый общий linear | Полный RMS | RMS среднего | Centered RMS |
| --- | ---: | ---: | ---: |
| Исходный h, initial | 2,401 | 1,581 | 1,806 |
| Private, initial | 0,486 | 0,444 | 0,199 |
| h×0,25, initial | 0,600 | 0,395 | 0,452 |
| h×0,25, best | 0,982 | 0,527 | 0,828 |
| Private при h×0,25, best | 1,460 | 1,133 | 0,920 |

Исходное отношение изменяющихся вкладов≈9,1; после gain0,25 в initial≈2,3,
в выбранной обученной policy≈0,9. Среднее объясняет44% второго момента h,
а не весь его большой масштаб. В исходной private-ветке среднее объясняет83%.
Следовательно, только сравнение полного RMS недооценивает перекос начальных
изменений. Это не измерение чувствительности именно к цели: private содержит
также физику/историю, ветви коррелируют, их вклады не независимы.

### Проверка функциональной эквивалентности

```bash
.venv/bin/python3 scripts/audit_arm_scale_equivalence.py
```

На тех же5400 состояниях выполнено `h'=0,25h`, `W_h'=4W_h`.
Для prediction head аналогично `W'=4W`. Остальные веса и bias неизменны.
Идентичность `W'h'=Wh` сохраняет следующий линейный выход, а значит и всю
последующую сеть. В actor/critic компенсируется только блок колонок для h,
private-блок не меняется.

Максимальная абсолютная разница **0,0**: prediction output20, action parameters12
и V. Проверены initial/best исходного frozen-gain1 и gain0,25. Веса/buffers не
менялись, только временные tensor-копии; новых физических rollouts нет.
Результат — ignored `runs/arm_conditioning/scale_equivalence.json`.

Следовательно, контроллер той же ширины/глубины **может представить** полностью
эквивалентную функцию при другом масштабе. Опыт не показывает, что PPO сам
найдёт её. Совместная supervised-подгонка readout и обучение новой policy по
вознаграждению — разные условия. Прежнее улучшение при gain0,25 согласуется
с изменением оптимизации; специфическую пользу предобученных признаков,
достаточность глубины и качество credit assignment этим не разделили.

## Опыт с глубиной

```text
27 causal inputs → predictor encoder4×128 → h128 → linear20 → прогноз
                                           │
full153 → actor-private2×128 ────────────────┼→ concat256 → post layers → Beta6
full153 → critic-private2×128 ───────────────┴→ concat256 → post layers → V
```

Actor/critic имеют независимые веса после замороженного encoder. Увеличиваем
именно число слоёв **после concat**, чтобы обрабатывать сочетания физических
признаков, цели и истории.

| Участок | Контроль | Новый опыт |
| --- | --- | --- |
| Predictor encoder/head | Frozen4×128 SiLU/linear20 | Тот же checkpoint |
| Private actor/critic | По2×128 SiLU | Без изменения |
| После concat | По2×128 SiLU | По4×128 SiLU |
| Gain h | 0,25 | 0,25 |
| Learning rate | 3e−4 | 3e−4 |
| PPO-параметров | 172941 | 238989 |
| Всего параметров | 228641 | 294689 |

Сохраняются все общие исходные веса reference `gain_025/initial.zip`, а не
обученные actor/critic. Два новых слоя в каждой ветви добавляются после прежних
двух: orthogonal gain√2, zero bias, отдельный фиксированный Torch seed0 внутри
fork_rng. Общий Torch RNG после инициализации совпадает с контролем.
Дополнительные SiLU меняют исходную функцию: идентичность исходных выходов не
заявляется. Это обычная более глубокая MLP без новых residual-связей или LayerNorm.
RMSprop создаётся заново с включением новых параметров.
Все CLI устанавливают `torch.set_num_threads(1)` до создания моделей;
побитовая независимость инициализации от числа CPU-потоков не заявляется.

Физика,153 наблюдения, Beta6,20-ms команды,40-ms delay,activation15/50 ms,
series elasticity,1 kg, награда и27 TRAIN_CASES прежние. PPO и stopping rule
из gain0,25 сохраняются: до131072 переходов; отсутствие1% rank-aware progress
49152 перехода после65536. Validation9 каждые8192, best по прежнему rank;
goal-balanced метрика дополнительно. Best hash фиксируется до test11,
last показывается отдельно. Набор уже использовался для предыдущих опытов;
это сравнение одного seed, не новый независимый benchmark.

Для исключения случайного изменения протокола общий rollout/validation/selection
цикл вынесен в `train_arm_conditioning.fit_policy`. Старые core/conditioning
модули и checkpoints не меняются; новая глубина имеет отдельный identity/loader.

```bash

.venv/bin/python3 -m myo.train_arm_depth evaluate
```

## Выводы глубины

При сохранённых gain0,25 и PPO3e−4 увеличение2→4 слоёв после concat **не помогло**
этому запуску. Одинаковый бюджет131072 перехода дал3662 optimizer steps против5829;
KL-stop106/128 против85/128. Best test ухудшился10,400→33,856°,
pass2/11→1/11. Единственный проход выбранной глубокой policy —покой15→15°.
Last получил30,865°;2/11 (15→15° и удержание120°), но не выбран заново по test.
Оба test без physical failures. Уверенного подъёма/опускания не получено.

Новый best выбран на98304: validation28,066°;1/9, только105→105°.
Последний validation29,217°;0/9. Остановка по максимальному бюджету, не по
доказанной сходимости. Непрерывное демо16 s с начальными20° осталось внизу
(конечные15,81/15,18/16,26/15,43°); capacity proxy0,9791 не поддерживает
объяснение провала быстрым утомлением.

Проверка h на том же5400-state batch дала mean-|Δu|0,03103 при замене h
средним и0,04108 при перестановке. Exact joint KL соответственно1,329/2,105.
Зависимость от физических признаков сохранилась; больше слоёв не превратило
её в лучшее управление. Это не проверка всех возможных форм схлопывания
внутренних слоёв или способности выделять именно целевые признаки.

**Ответ на исходный вопрос:** обученная prediction head уже согласована со своим
encoder и физической MSE-задачей. Новые actor/critic учат другое отображение,
с добавлением private/goal-ветви и сигналами PPO. Масштаб сам по себе не
ограничивает класс функций —его можно компенсировать весами, что проверено
численно. Но он меняет начальное смешивание сигналов, градиенты и последующую
оптимизацию. Данные поддерживают важность этих условий, а не вывод о том,
что замороженные признаки невозможно прочитать контроллером.

Сравнение не разделило возможный выигрыш выразительности от усложнения
оптимизации: дополнительные SiLU изменили начальную функцию, число parameters
и KL-динамику. Первый общий слой256→128 и настройка нормировки остались прежними.
Другие learning rate для глубокой версии не проверялись; глобальная непригодность
глубоких сетей или единственная причина неуспеха PPO не установлены.
