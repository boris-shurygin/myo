# Телеметрия V2 и локальные команды

Реализация: `src/myo/telemetry.py`, `src/myo/control.py`. Снимки состояния
`myo.character_state.v2` заменяют V1: теперь геометрия и силы поверхности относятся
к конечной позе, а приложенные на последнем подшаге силы выделены явно.
Есть Python-получатель команд; получатель состояния в Unreal ещё предстоит.

## Транспорт и время

JSON UTF-8: один объект на строку JSONL или на UDP datagram. Сеть ограничена
`127.0.0.1`. `run_id` различает запуски, `sequence` монотонен в запуске,
`episode` увеличивается при reset. Время симуляции начинается заново с эпизодом.
Каждый пакет — полный снимок, NaN/Infinity запрещены. Получатель должен
отбрасывать устаревшие пакеты, показывать потерю потока и не интерполировать
между эпизодами. Шаг физики не зависит от FPS или наличия получателя.

`simulation_time_s` — время позы, активации, capacity, длины волокна и геометрии
сухожилия. После `mj_step2` обновляются кинематические данные; `sample()` пересчитывает
длину и натяжение сухожилия при том же состоянии волокна, без второго шага
задержки/активации. Невязка равновесия этого снимка отражает расщепление интегратора.
`fiber_velocity_m_s` — оценка скорости по последнему шагу состояния волокна.

`applied_force_time_s` и `applied_*` описывают силы последнего решения перед
`mj_step2`, использованные для движения. Их нельзя подменять силами конечного
снимка при проверке работы/момента. На reset этот канал содержит начальное
равновесие, физический шаг ещё не выполнен. Подробнее: [модель](model.md).

## Состояние

| Поле | Смысл |
|---|---|
| `schema`, `model` | V2; `myoarm_1dof` или `preacher_curl_1dof_v0` |
| `config_sha256`, `dynamics_sha256`, `geometry_sha256` | Конфигурация, реализация с версией MuJoCo, проверенные исходные/подготовленные assets |
| `physics_dt_s`, `control_dt_s` | Шаги физики и управления |
| `coordinates` | Правая система, Z вверх, метры и радианы |
| `joints[]` | Угол, скорость, сглаженная цель и её скорость; `limits_rad` с `null` для отсутствующей границы |
| `command` | Запрошенная цель, trigger `[0,1]`, источник reference/manual/curriculum |
| `payload_mass_kg` | Масса груза текущего эпизода, меняется только при reset |
| `body_poses[]` | Имена MuJoCo bodies, мировые позиции и кватернионы **wxyz** |
| `muscles[]` | Состояния шести мышц MyoArm или четырёх toy-приводов |
| `surface_state` | Время входов деформации; кожа и объёмная деформация пока отсутствуют; обратной связи в физику нет |
| `prediction` | `null` либо прогноз, горизонт и hash отдельного predictor |
| `metrics` | Ошибки, моменты, прокси, компоненты reward, невязка и пики подшагов |

У каждой мышцы отдельно передаются:

- `excitation_command`, `excitation_delayed`, `activation`: три разных сигнала `[0,1]`;
- `tendon_force_N`, `applied_tendon_force_N`, `reference_max_force_N`, `force_normalized`;
- `fiber_length_m`, `fiber_velocity_m_s`, `tendon_length_m`, `musculotendon_length_m`;
- `tendon_strain`, `moment_arm_m`;
- `active_fiber_force_N`, `passive_fiber_force_N`, `damping_force_N`;
- `remaining_capacity`, `fatigue_proxy`.

Нормализованная сила может превышать 1; для цвета её можно ограничивать, исходные
числа сохраняются. `summed_tendon_force_proxy_N` не является контактной силой локтя.
`substep_peaks` объединяют состояния на границах физических подшагов и приложенные
силы, включая пик натяжения, strain, суммы сил, момента пассивного ограничителя,
скорости к пределу и реакции численного joint limit. Сила торможения также
нагружает сухожилия. Это инженерные показатели, не медицинские пороги.

У MyoArm `limits_rad` содержит нижнюю границу 15° в радианах и `null` сверху.
`metrics.path_direction_reversal` сигнализирует о смене анатомического
направления исходного мышечного пути при экстраполяции. Этот флаг не меняет
силы и не является новым ограничителем движения.

## Канал команд

```bash
python3 -m myo demo --config configs/d1_myoarm.json \
  --udp-port 7001 --command-port 7002 --command-timeout 0.5
```

Отправитель узнаёт `run_id` и `episode` из текущего снимка. Пример datagram:

```json
{"schema":"myo.character_command.v1","run_id":"<из снимка>","episode":0,"sequence":1,"target_angle_rad":1.5,"trigger":0.7}
```

Получатель принимает только текущие run/episode и возрастающий sequence.
Некорректные, повторные и устаревшие команды отбрасываются. Цель ограничивается
существующими границами локтя (у MyoArm только снизу), затем проходит генератор скорости/ускорения. Пакет меняет
пользовательскую команду, не q/qvel или мышечные состояния.

Если пакет не пришёл за `command-timeout` секунд реального времени (также после
начала нового эпизода), ставится trigger=0: запрос расслабиться с сохранением
возможности защиты. Задержка, активация и груз остаются в обычном физическом
контуре. Новая корректная команда снимает timeout. Для внешнего ввода используйте
`demo` или `rollout --realtime`: headless без ограничения темпа идёт быстрее часов.

## Будущая визуализация кожи

Body transforms — это имена и позы конкретной MyoArm, не готовый универсальный
UE rig. Адаптер сопоставит bind pose/кости, переведёт метры в сантиметры и оси
на именованной границе визуализатора. Для Flesh доступны независимые активации,
длины волокон/сухожилий и натяжения. Они требуют настроенного отображения в
параметры тканей; навязать их все как независимые ограничения нельзя автоматически.

Кожа обязательна для полного D1. Сейчас пакет лишь предоставляет входы и честно
указывает отсутствие surface assets. ML Deformer при необходимости обучается
на позах и кривых мышечного состояния; новая runtime-кривая без соответствующих
обучающих данных не создаёт деформацию.
