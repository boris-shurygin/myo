# Телеметрия V1

Назначение — передавать вычисленное физическое состояние визуализатору. Это не
протокол удалённого управления и не полноценный формат humanoid rig.
Реализация: `src/myo/telemetry.py`; запуск — `myo rollout --output ... --udp-port ...`.

## Транспорт и порядок

- JSON UTF-8: один объект на строку JSONL или один объект на UDP datagram.
- UDP в V0 только на loopback `127.0.0.1`. Получатель UE ещё не реализован.
- `run_id` различает запуски. `sequence` монотонен внутри запуска.
- `episode` увеличивается при reset; `simulation_time_s` начинается заново.
- Визуализатор должен отбрасывать устаревшие пакеты, корректно обрабатывать reset
  и показывать состояние потери/устаревания потока. Интерполяция между эпизодами запрещена.
- JSON не допускает NaN/Infinity. UDP не обеспечивает доставку, поэтому каждый
  пакет содержит полный визуальный снимок, без зависимости от предыдущего delta.
- Фиксированный physics timestep не зависит от наличия UDP-получателя.

## Поля

| Поле | Смысл |
|---|---|
| `schema` | `myo.character_state.v1` |
| `model` | `preacher_curl_1dof_v0`; определяет фиксированную геометрию и сустав |
| `config_sha256` | Отпечаток полной конфигурации среды |
| `dynamics_sha256` | Отпечаток V0 env/muscle/delay/XML и версии MuJoCo; обнаруживает смену физической реализации |
| `run_id`, `sequence`, `episode` | Идентичность и порядок снимков |
| `simulation_time_s` | Время текущего эпизода |
| `physics_dt_s`, `control_dt_s` | Шаги физики и управления |
| `coordinates` | SI: метры, радианы; правая система, Z вверх |
| `joints[]` | `elbow`: угол, угловая скорость и текущая команда, rad/rad/s |
| `muscles[]` | Именованные состояния всех четырёх мышц |
| `prediction` | `null` без предиктора; иначе прогноз ошибки угла/скорости, горизонт и hash модели |
| `metrics` | Ошибки слежения, момент, proxies, компоненты reward и локальный residual |

Каждая мышца содержит:

| Поле | Единицы и значение |
|---|---|
| `name` | Стабильный идентификатор мышцы |
| `excitation_command` | `[0,1]`, команда до моторной задержки |
| `excitation_delayed` | `[0,1]`, доставленная команда |
| `activation` | `[0,1]`, состояние активации после её собственной динамики |
| `tendon_force_N` | Неотрицательное натяжение, N |
| `reference_max_force_N` | Номинальный параметр силы до fatigue |
| `force_normalized` | `tendon_force_N / reference_max_force_N`; может превышать 1 |
| `tendon_strain` | Положительное растяжение относительно slack length |
| `fiber_length_m`, `fiber_velocity_m_s` | Длина и скорость волокна |
| `remaining_capacity` | `[0,1]`, phenomenological available force fraction |
| `fatigue_proxy` | `1 - remaining_capacity`, не диагностическая оценка |

`summed_tendon_force_proxy_N` — сумма натяжений. Она показывает в том числе
coactivation, но не является анатомической контактной силой сустава. Для отрисовки
индикатора можно ограничить нормализованную величину; исходные N/strain в пакете
не следует заменять ограниченными значениями.

Состояния приходят из одной точки control loop. Из-за first-order split сила
последнего подшага рассчитана по геометрии перед `mj_step2`, тогда как угол —
после него. Это временной сдвиг не более одного physics step, описанный в
[model.md](model.md); пакет не является повторным решением ткани на новой позе.

## Привязка к UE

В V0 передаётся угол одного заранее известного сустава. Humanoid bone transforms,
bind pose, свободный root и преобразование кватернионов будут версионированным
расширением. Нельзя трактовать этот пакет как готовую поддержку произвольного
SkeletalMesh. Перевод метров в сантиметры, ориентаций и осей выполняет адаптер.

Предлагаемые curve names для первой мышцы:

- `biceps_long_activation` ← `activation`;
- `biceps_long_force_normalized` ← `force_normalized`;
- `biceps_long_tendon_strain` ← `tendon_strain`;
- `biceps_long_capacity` ← `remaining_capacity`.

Точный набор входов ML Deformer выбирается **до обучения его модели**. Добавление
curve в runtime без соответствующего обучающего набора не создаёт новый эффект.
