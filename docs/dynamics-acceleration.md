# Ускорение как цель предиктора — 2026-11-05

По запросу владельца проверена замена скоростной части loss на ускорение.
Использована большая сеть `26→1024→1024→512→20` (1612308 параметров) и те же
эпизоды/состояния, что в [предыдущем опыте](dynamics-prediction.md).
Физика MyoArm, масса 1 kg, шаги 1/20 ms, задержка 40 ms, динамика активации,
упругие сухожилия, capacity proxy и контакт не менялись. Actor не обучался.

## Что именно изменилось

Ускорение определено как **среднее за управляющий интервал**:
`a_k = (v_k − v_(k−1)) / .02 s`. Это не мгновенный `mjData.qacc` в конце шага.
Прогноз на горизонте 120 ms означает здесь ускорение интервала **100–120 ms**,
а не среднее ускорение от начала до 120 ms.

Прежняя residual MLP уже предсказывает приращение скорости. На одном шаге
с известной начальной скоростью нормированная ошибка ускорения тождественна
прежней ошибке скорости:

`((v_hat − v_0)/dt − (v_true − v_0)/dt) / (sigma_delta_v/dt)`
`= (v_hat − v_true) / sigma_delta_v`.

Поэтому отдельное повторение one-step оптимизации не является новым опытом.
Его checkpoint скопирован из большой сети без обновления весов и служит
контролем. В тесте проверены равенство самой loss и градиентов в float64.

Содержательное изменение сделано в BPTT на шести шагах. Обозначим ошибку
скорости `e_k = v_hat_k − v_true_k`, `e_0 = 0`:

- раньше штрафовалась накопленная ошибка `e_k / sigma_delta_v`;
- теперь штрафуется локальная разность `(e_k − e_(k−1)) / sigma_delta_v`.

Предыдущее **предсказанное** состояние остаётся входом следующего шага.
Реальные промежуточные состояния участвуют только в метках ускорения. Все
остальные 19 каналов loss, их веса, MLP, normalization и очередь остаются
прежними. Скорость при разворачивании восстанавливается прибавлением
предсказанного приращения — это явное представление ускорения через `delta_v`.
Одного переименования выхода или изменения единиц для нового опыта было бы
недостаточно.

Данные и разбиение 36/18/18 целых эпизодов скопированы побайтно. Один seed 0,
та же инициализация большой MLP, одинаковые minibatch, Adam lr .001, batch 128,
clip norm 10, 2000 обновлений, проверки через 100 обновлений. Настроек reward,
GAE или critic здесь нет. Это один ограниченный запуск, не доказательство
сходимости или невозможности дальнейшего улучшения.

До просмотра test заданы два критерия выбора checkpoint на validation:
средняя RMSE ускорения на интервалах с концами 20/60/120 ms и прежняя средняя
RMSE скорости в эти моменты. Второй позволяет отделить смену loss от смены
критерия выбора. Оба выбрали **update 1600**, с одинаковыми весами. Это два
сохранения одной учебной траектории, а не два независимых запуска.

## Результат

RMSE среднего ускорения, rad/s², на 18 test-эпизодах:

| Интервал относительно начала прогноза | Прежний BPTT, loss скорости | Новый BPTT, loss ускорения |
| --- | ---: | ---: |
| 0–20 ms | 10.006 | 10.397 |
| 40–60 ms | 9.412 | 9.727 |
| 100–120 ms | 10.154 | 10.219 |
| 380–400 ms | 10.412 | 10.300 |

Смена loss не дала устойчивого выигрыша даже по ускорению. Baseline нулевого
ускорения имеет RMSE 16.989/16.984/16.939/15.969 rad/s² на этих интервалах:
обе сети точнее него, но резкие торможения/отскоки всё ещё размазываются.

RMSE восстановленной скорости, rad/s:

| Горизонт | Прежний BPTT | Новый BPTT |
| --- | ---: | ---: |
| 20 ms | .20012 | .20794 |
| 120 ms | .33813 | .40916 |
| 400 ms | .36360 | .43273 |

Ухудшение скорости на 120 ms около 21%. Локальный критерий математически
слабее штрафует постоянное смещение скорости: после появления смещения оно
не добавляет ошибку ускорения каждый следующий шаг. Это объясняет различие
целей обучения, но не доказывает единственную причину измеренного ухудшения.

На тех же 36 native-пробах новая сеть лучше прежней воспроизводит некоторые
производные, но надёжного градиента по-прежнему не даёт:

| Метрика после задержки, интервалы до 120 ms | Прежний BPTT | Новый BPTT |
| --- | ---: | ---: |
| RMSE Jacobian скорости / возбуждения | 1.121 | .772 |
| Общий cosine Jacobian скорости | .277 | .365 |
| Знак значимых производных скорости совпадает | 72.06% | 76.11% |
| RMSE Jacobian ускорения / возбуждения | 60.915 | 37.746 |
| Общий cosine Jacobian ускорения | .078 | .111 |
| Знак значимых производных ускорения совпадает | 58.79% | 59.80% |

Для скорости порог значимости .05 rad/s на единицу возбуждения; для ускорения
он масштабирован в 2.5 rad/s². Ускорительные Jacobian получены разностью
соседних скоростных Jacobian, делённой на .02 s. Начальная скорость не зависит
от новой команды. Это те же численные пробы исходного MuJoCo с неизменными
последующими командами; новых физических ответвлений для этого пересчёта нет.
Нулевой Jacobian имел бы RMSE 10.489 для ускорения: выученная чувствительность
всё ещё существенно неточна. На 60 ms неправильное направление вектора
скоростных производных встречается в 5/18 состояний против 11/18 у прежней
большой BPTT; на 120 ms — 2/28 против 3/28. Эти счётчики не являются оценкой
процента неправильных обновлений actor.

На 120 ms ошибка ускорения новой сети при входе из ≥30° в область <30° —
55.667 rad/s² (60 окон), при движении целиком внутри 30–130° — 3.878 rad/s²
(310 окон). Границы здесь диагностические, не медицинские/анатомические
пороги и не точный детектор контакта. Негладкие переходы остаются важным
источником ошибки. Причинный эксперимент по их охвату ещё не проводился.

## Запуск и артефакты

```bash
.venv/bin/python3 -m myo.train_dynamics_acceleration \
  --reference runs/d1_dynamics_prediction_wide \
  --output-dir runs/d1_dynamics_acceleration \
  > runs/d1_dynamics_acceleration.log 2>&1
PYTHONPATH=/tmp/myo-supervised-plot-deps MPLCONFIGDIR=/tmp/myo-supervised-mpl \
  .venv/bin/python3 scripts/evaluate_dynamics_prediction.py \
  --run runs/d1_dynamics_acceleration \
  --reference-run runs/d1_dynamics_prediction_wide \
  --run-label 'acceleration loss' --reference-label 'velocity loss' \
  --comparison-title 'Wide dynamics model: velocity loss vs interval acceleration loss' \
  --acceleration --plot > runs/d1_dynamics_acceleration_evaluation.log 2>&1
```

193.78 s, exit 0. Новый сбор эпизодов: 0 шагов. Native-аудит: 2808 управляющих
шагов, его эталонный Jacobian точно совпал с предыдущим опытом. Проверено
окружение Python 3.12.16 / PyTorch 2.15.0+cpu; GPU не использован. Времена
не являются изолированным benchmark, поскольку параллельно выполнялся pytest.

обучающую цель и hash trainer. Inference-контракт прежней большой модели
сохранён: архитектура/порядок состояния/физический переход не менялись.
Предыдущие исходники и checkpoints не переписаны. Исходник предыдущего evaluator
сохранён в игнорируемом каталоге большой сети как `evaluate_source_v2.py`.
